## 1. 项目概述

### 1.1 目标

- 浏览器内稳定 60 FPS 运行，打开网页即玩，无需安装。
- 完整的格斗游戏骨架：移动、普通技、搓招特殊技、超必杀、防御、连段、气槽、回合制。
- 路飞与赤犬两个手感差异明显的角色，各自约 6 个特殊技、2 个超必杀、1 个终极技、1 个特色机制。
- 一张舞台，一套完整流程：标题 → 模式选择 → 选人 → 战斗 → 结算。
- 支持本地双人（同一键盘或两个手柄）与人机对战。
- 架构上为后续扩展留门：新增角色只加数据和素材，不改核心代码；核心逻辑确定性（deterministic），为将来联机、回放留可能。

### 1.2 第一版明确不做

- 联机对战（rollback 网络同步难度极高，留到后期）。
- 3v3 组队制（拳皇特色，但先把 1v1 打通）。
- 超过 2 个角色、超过 1 张舞台。
- 剧情模式、街机模式。
- 商业发布（版权原因，见第 7 节）。

### 1.3 成功标准

- 一局完整对战不刷新页面即可走完，且没有明显 bug。
- 用占位素材也能感受到"格斗游戏手感"：打击定格、击退、连段、搓招稳定识别。
- 两个角色打法不同：路飞靠机动和连段，赤犬靠压制和高伤。
- 找 2～3 个朋友试玩后愿意再打一局。

## 2. 调研

### 2.1 拳皇（KOF）核心机制拆解

| 机制 | 说明 | 第一版 |
|---|---|---|
| 4 键制 | A 轻拳 / B 轻脚 / C 重拳 / D 重脚 | 做 |
| 站 / 蹲 / 跳 普通技 | 每个键 3 种姿态，共 12 个普通技 | 做 |
| 特殊普通技 | 如 前+C，多为中段（overhead） | 做 |
| 前冲 / 后撤步 | →→ / ←← | 做 |
| 4 种跳跃 | 普通跳、小跳、大跳、中跳 | 先做普通跳 + 小跳 |
| 紧急回避（翻滚） | A+B，前 / 后翻滚，打击无敌但可被投 | 做 |
| 吹飞攻击 | C+D，重击吹飞撞墙 | 做 |
| 投技 | 近身 ← / → + C 或 D，可拆投 | 做 |
| 上下段防御 | 按住后方向；蹲防挡下段，中段必须站防 | 做 |
| 气槽 | 最多 3 格，攻击 / 被击积累，回合间保留 | 做 |
| 超必杀 | 消耗 1 格 | 做 |
| MAX 超必杀 | 消耗 2 格的强化版 | 后期 |
| MAX 模式 | 耗气进入强化，可自由取消 | 后期 |
| 防御取消翻滚 / 吹飞 | 防御硬直中耗气反击 | 后期 |
| 倒地受身 | 落地瞬间按键快速起身 | 做 |
| 反击（Counter Hit） | 打中对方出招前摇，伤害和硬直加成 | 做 |
| 3v3 组队 | 队伍轮换、气槽继承 | 后期 |

参考对象：

- 《拳皇 XIII》《拳皇 XV》：系统和帧数据参考（Dream Cancel wiki 有完整帧数据）。
- 《海贼王 大海贼斗技场》（One Piece: Great Pirate Colosseum，3DS，2016）：官方出的海贼王 2D 格斗游戏，路飞和赤犬都是可用角色，是招式设计和精灵风格最直接的参考。
- 《海贼王 巨人战斗！2 新世界》（Gigant Battle! 2，NDS，2011）：2D 像素精灵，含赤犬。
- Footsies（开源极简格斗游戏）：理解格斗游戏基本功（间距、帧、防御）的最小样本。
- Ikemen GO（开源、兼容 MUGEN 的引擎）：状态机和判定框数据结构的参考。

### 2.4 美术素材来源调研

美术是这个项目最大的成本和最大的风险。一个格斗游戏角色需要约 40 个动作、200～300 帧精灵图。

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 官方 2D 游戏精灵图（The Spriters Resource 上的 NDS《巨人战斗》、3DS《大海贼斗技场》拆包） | 质量高、动作齐全、风格统一，路飞和赤犬都有 | 有版权；分辩率低（NDS 角色约 64～96 像素高，3DS 约 128 像素）；需要按我们的帧数据重新切分对齐 | 个人学习用途推荐 |
| B. MUGEN 社区角色 | 路飞、赤犬都有多个版本，自带判定框 / 帧数据（.air / .cns 文件）可参考；可用 Fighter Factory 导出 PNG | 同样有版权；不同作者风格不一致 | 作为 A 的补充和帧数据参考 |
| C. 自绘像素画（Aseprite） | 完全可控，风格统一 | 工作量极大（每角色 200+ 帧），角色形象本身仍有版权 | 只在后期确定要公开发布时考虑 |
| D. AI 生成 | 立绘、头像、背景、UI 素材效率高 | 动画帧之间一致性差，需大量后处理 | 用于立绘 / 背景 / UI，不用于动作帧 |
| E. 3D 模型预渲染（MMD 路飞模型等） | 姿势可控，帧数无限 | 管线复杂，风格与像素格斗游戏不搭 | 不推荐 |
| F. 占位素材（色块 + 判定框） | 零成本，立即可用 | 没有观感 | 阶段 1～2 必须用，让玩法先跑起来 |

推荐路线：F（占位）→ A + B（角色动作帧）→ D（立绘、背景、UI）。素材不进公共 Git 仓库，只放本地或私有存储。

### 2.5 音频

- 背景音乐：顶上战争原声（版权）或免版权替代（OpenGameArt、Freesound），也可用 AI 生成。
- 打击音效：轻击、重击、防御、投技、KO，Freesound 可找到；橡胶伸缩音、熔岩喷发音需要单独找或合成。
- 角色语音：原作语音片段（版权），第一版可以没有语音。

## 3. 技术方案

### 3.1 选型对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| Phaser 3 + TypeScript + Vite | 最流行的 2D 网页游戏框架；资源加载、精灵动画、输入、音频、场景、粒子齐全；文档和社区多；AI 辅助编码效果好 | 默认可变步长，需要自己实现固定步长逻辑；打包体积约 1 MB | 推荐 |
| PixiJS + 自写逻辑 | 渲染性能强，体积小 | 输入、音频、场景、动画管理全要自己写 | 备选 |
| 原生 Canvas + TypeScript | 完全可控，零依赖 | 造轮子多 | 学习目的可选 |
| Godot 4（HTML5 导出） | 完整引擎，多平台一键导出 | 网页导出体积大、浏览器兼容性坑（SharedArrayBuffer）；GDScript 与 Cursor 的协作不如 TypeScript | 若后期重点转桌面 / 移动端可考虑 |
| Unity WebGL | 生态强 | 网页包巨大、加载慢 | 不考虑 |

### 3.2 推荐技术栈

- 语言：TypeScript
- 游戏框架：Phaser 3.90（2026-09 时 Phaser 4.2 已发布；选 3.x 是因为文档、示例与社区答案覆盖更全，且本项目只用 Phaser 做渲染与输入，后续迁移成本低）
- 构建：Vite
- 测试：Vitest（只测核心逻辑：连段、帧数据、命中判定，全部确定性可复现）
- 图集打包：TexturePacker 或 free-tex-packer
- 判定框编辑：第 3 阶段评估是否自制一个网页版 hitbox 编辑器
- 代码规范：ESLint + Prettier
- 部署：GitHub Pages / Vercel / Cloudflare Pages（纯静态）

### 3.3 架构：逻辑与渲染分离

核心思想：格斗逻辑（`core`）不依赖 Phaser，是一个纯 TypeScript 的确定性模拟器。输入是每帧两名玩家的按键位图，输出是世界状态；Phaser 只负责画出来、播声音、收输入。

```
键盘 / 手柄 → InputMapper → InputFrame(P1, P2) → FightSim.step()   固定 60 Hz
                                                       │
                                                       ▼ WorldState（位置、状态、帧号、HP、气）
                                             FightScene（Phaser 渲染层）
                                             ├─ FighterView   精灵与动画同步
                                             ├─ HUD           血条、气槽、计时器、连段数
                                             ├─ FX            打击火花、震屏、粒子
                                             └─ DebugOverlay  判定框、帧数据面板
```

好处：可以单测；可以只存输入序列做录像回放；训练模式可以随时回退；将来做联机（rollback）有基础；换渲染层不影响玩法。

### 3.4 关键技术点

1. 固定步长：用累加器把渲染帧转成 60 逻辑帧 / 秒，格斗游戏的帧数据必须建立在固定步长上。
2. 输入系统：每帧一个快照（方向 + 4 键的位图），保留最近 60 帧的环形缓冲；指令识别有容错窗口（摇杆动作约 10 帧内完成，按键缓冲 3～4 帧）；面朝左时自动镜像输入；训练模式显示输入历史。
3. 状态机 + 帧数据：每个动作是一个状态，每帧包含精灵帧、hurtbox（受击框）列表、hitbox（攻击框）列表、pushbox（推挤框）、位移速度、可取消窗口、无敌标志。
4. 碰撞判定：全部用 AABB 矩形；pushbox 互相推开避免重叠；hitbox 碰到 hurtbox 即命中，每次攻击对同一目标只命中一次；双方同一帧互相命中为相杀。
5. 命中结算：伤害（带连段衰减）、受击硬直、防御硬直、击退（地面 / 空中不同）、打击定格（hitstop，双方定格数帧，手感的关键）、浮空与浮空次数限制、倒地类型（软倒可受身 / 硬倒不可）。
6. 摄像机：跟随两人中点，限制在舞台范围内；两人最大间距等于屏幕宽减边距，形成"拉扯边界"。
7. 数据驱动：角色 = 招式表（`moves.ts`，TypeScript 常量以获得类型检查；若后期做可视化编辑器再导出 JSON）+ 精灵图集 + 动画表，新增角色不改核心代码。
11. 输入锁存：按下与松开若发生在同一逻辑帧内，仍要在下一帧出现一次（M1 实测：不锁存时快速轻点约 95% 被吞）。
8. 确定性：位置用整数（例如 1/256 像素为单位）或严格固定步长下的浮点；随机数用可指定种子的生成器。
9. 调试工具：F1 显示判定框，F2 帧数据面板（当前状态、帧号、硬直剩余），F3 输入显示，训练模式支持慢放和逐帧。
10. 性能：单张图集不超过 4096×4096；特效对象池化；避免逐帧产生垃圾。

## 4. 游戏设计

### 4.1 基础规则

- 3 局 2 胜，每局 99 秒（可设 60 / 99 / 无限）。
- 血量：路飞 1000，赤犬 1100（所有数值均为初始值，待实测调整）。
- 时间到时血量高者胜；双方同时 KO 为平局，该局重打。
- 气槽：3 格，每格 100 点；攻击命中积累最多，防御成功和被击也少量积累；回合之间保留。
- 逻辑分辩率：若走像素素材路线，原生 480×270，整数倍放大到窗口；若走高清素材路线，1280×720。见第 8 节决策。

### 4.2 操作与键位

| 移动 / 跳 / 蹲 | W A S D | 方向键 | 左摇杆 / 方向键 |
| A 轻拳 | J | 小键盘 1 | X |
| B 轻脚 | K | 小键盘 2 | A |
| C 重拳 | U | 小键盘 4 | Y |
| D 重脚 | I | 小键盘 5 | B |

| 暂停 | Esc | Esc | Start |

### 4.3 通用系统

- 移动：行走、蹲、普通跳（前 / 后 / 垂直）、小跳（轻点上）、前冲（66）、后撤步（44）。
- 防御：按住后方向。站防挡上段和中段，蹲防挡上段和下段，中段（overhead）必须站防；没有空中防御（拳皇传统）。
- 投技：近身 4 或 6 + C，启动 4 帧，对方同时输入可拆投。
- 翻滚（A+B）：前 / 后翻滚，全程对打击无敌，可被投，收招有硬直可被惩罚。
- 吹飞（C+D）：启动慢，命中吹飞撞墙弹回可追击，防御也造成大量击退。
- 取消链：轻普通技 → 重普通技（仅命中或被防御时）→ 特殊技 → 超必杀 → 终极技；第一版特殊技之间不互相取消。
- 连段衰减：第 n 段伤害乘以 max(0.3, 1 − 0.1 × (n − 1))。
- 浮空限制：空中连续受击不超过 3 段，之后强制倒地。
- 倒地：软倒可受身（落地瞬间按键快速起身），硬倒不可；起身到可操作之前无敌。
- 反击（Counter Hit）：打中对方出招前摇时，伤害 +25%，硬直更长，屏幕提示 COUNTER。
- 相杀：同一帧互相命中，双方都吃伤害。
- KO 演出：最后一击打击定格拉长，慢镜头，"K.O." 字样。
- 第一版不做：眩晕、防御值 / 破防、MAX 模式。

### 4.6 平衡与对局设计

- 一套完整连段的伤害目标是 30%～40% 血量，保证一局能打 3～4 个回合的攻防。
- 路飞每次接近都有风险（大喷火、熔岩地裂），但接近后回报高（机关枪连段、回旋弹破霸体）。
- 赤犬远程有两种工具（犬噛红莲走地面、流星火山从天上来），迫使路飞既要弹反又要跳，但都有明显前摇，被跳进来就要挨连段。
- 灼烧让赤犬"擦到就赚"，补偿他连段能力差；熔岩化给赤犬一个脱困手段，但要花气。
- 所有数值第 3 阶段用训练模式实测后再调。

### 4.7 舞台：马林梵多

- 背景分三层做视差滚动：远景（天空、海、海军本部建筑群），中景（处刑台、海军旗），近景（广场地面与碎冰）。
- 舞台宽度约 2.2 个屏幕，左右有墙（撞墙是吹飞和火箭炮的一部分）。
- 动态元素：飘落的灰烬与火星粒子；背景人群剪影可选。
- 后续候选舞台：香波地群岛、推进城、司法岛、和之国。

### 4.8 界面与流程

```
Boot → Preload（进度条）→ Title（按任意键）
  → ModeSelect：双人对战 / 人机对战 / 训练模式 / 设置
  → CharacterSelect：P1 / P2 选人（路飞、赤犬），可选配色
  → Fight：每回合  入场 → "READY / FIGHT!" → 对战 → "K.O." 或 "TIME OVER" → 胜利姿势
  → Result：再来一局 / 重新选人 / 回标题
```

- HUD：上方双层血条（当前血量 + 延迟消退的红条）、头像、名字、局数小标、中央计时器；下方气槽（3 格）；侧边连段计数（"5 HITS!" 与总伤害）；系统提示（COUNTER、REVERSAL）。
- 暂停菜单：继续 / 键位设置 / 回选人 / 回标题。
- 训练模式：无限血与气、显示判定框、帧数据面板、木桩设置（站 / 蹲 / 跳 / 防御 / 随机 / 受身）、录制与回放、重置位置。
- 视觉风格：顶上战争主题，海军深蓝配熔岩橙红；标题和提示用粗体斜切字体（拳皇风格）；UI 文字中文，"FIGHT!"、"K.O." 等保留英文（格斗游戏惯例）。

## 附录 A：招式数据格式示例

以路飞的"橡胶火箭炮"为例，说明数据驱动的招式定义。判定框格式为 `[x, y, 宽, 高]`，坐标以角色脚下中心为原点、面朝右。

```json
{
  "id": "gomu_bazooka",
  "name": "橡胶火箭炮",
  "nameJp": "ゴムゴムのバズーカ",
  "type": "special",
  "input": { "motion": "214", "buttons": ["A", "C"] },
  "meterCost": 0,
  "meterGain": { "hit": 15, "block": 8, "whiff": 3 },
  "damage": 120,
  "guard": "mid",
  "hitstun": 24,
  "blockstun": 18,
  "hitstop": 10,
  "knockback": { "x": 18, "y": 0, "wallBounce": true },
  "cancelInto": ["super", "ultimate"],
  "animation": "special_bazooka",
  "frames": [
    { "sprite": 0, "duration": 6,  "hurtboxes": [[-30, -160, 60, 160]], "pushbox": [-25, -160, 50, 160] },
    { "sprite": 1, "duration": 8,  "hurtboxes": [[-30, -160, 60, 160]], "pushbox": [-25, -160, 50, 160], "velocity": { "x": 2 } },
    { "sprite": 2, "duration": 4,  "hurtboxes": [[-30, -160, 60, 160]], "pushbox": [-25, -160, 50, 160],
      "hitboxes": [[40, -120, 140, 60]] },
    { "sprite": 3, "duration": 22, "hurtboxes": [[-30, -160, 80, 160]], "pushbox": [-25, -160, 50, 160] }
  ]
}
```

对应帧数据读法：启动 14 帧（6 + 8）、持续 4 帧、收招 22 帧，总计 40 帧。
