## 判断与已定取舍

【判断】优先验证本地 Qwen3-TTS，GPT-SoVITS 作为日语备选。免费网页保留作试听/备用渠道。停止为当前日语目标继续批量审普通话旧稿，先把青雉一角从声音生成走到真实游戏播放，再复制流程。

用户本轮明确选择：**日语为主，接受相近的合成声线**。因此可以按性格设计原创声线，不必等待原作演员的干净录音。已验收旧四角和LABUBU/星星人声音保持；新合成不称“原作原声”。

最强反方：本地安装本身可能比网站试用更耗时，能朗读日语也不能证明能做好格斗喊叫。故不同时装四套模型，不先生成全阵容；一次只验证一条路线、一个角色、少量有代表性的台词。固定声音后的短喊不自然，就切备选，不靠调响音量冒充情绪。

## 实施顺序与明确停止条件

```mermaid
flowchart LR
    A[角色声线与日语台词] --> B[生成少量原始声音]
    B --> C[核对发音和听感]
    C --> D[保存角色声音配置]
    D --> E[接入已有事件与字幕]
    E --> F[真实对局播放]
    F --> G[完成角色其余缺项后发布]
```

1. **先青雉小样**：平静选人、短促技能名、受击各一条，日语正文、假名读音、中文意思同时记录。固定声音后再补一条新句，验证声音能够复用。只使用原创描述/自制参考，不新增原作音频外发。
2. **只部署主选模型**：沿D盘隔离工具约定先核实际磁盘/RAM/GPU，保留现有模型和服务；先查依赖与权重下载体积，再在独立环境做单条。VoiceDesign/Base分阶段加载，不与重型Omni听核同时常驻。未做资源实测前不承诺速度与显存。
3. **听核不绑死一个重模型**：自动检查采样、削波、静音和文件损坏；日语识别只辅助检查错词。沿已有通用门禁，用真实可处理音频的模型或用户对精确片段的试听记录确认实际发音/截断/杂音。不能用生成文本或转写冒充听感。用户听样需求集中在一个完整小样包，不逐条让用户审批。
4. **复用游戏管道**：保存原件/参数/版本/SHA/实际台词，采用后输出现有运行格式，更新同一来源与事件/字幕映射。选人、出力、受击、KO、胜利、待机、移动逐项登记；共用出力与专属喊招明确区分。模型不放进游戏运行包。
5. **一次必要实机**：真实触发样本事件，检查日语字幕、音量与BGM、事件重叠和截断。无阻断即停止扩验，再完成该角计划声音项；不先产119条再发现语言/声音不合适。
6. **扩新角色**：每角新增声音描述或自制参考、台词与假名表、事件映射。共用导出/校验/采用管道，保留逐角“已生成/已听核/已接入/实机通过”状态。动作、技能与投技仍独立闭环。

替换条件：Qwen在固定声线后短喊表现不合格，或本机依赖/资源单条实证失败，则只切GPT-SoVITS；如主要差距是情绪，再评估IndexTTS2.5，不并行安装所有模型。无可靠新证据不重复同一路径的失败加载。
