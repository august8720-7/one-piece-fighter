# 完整动漫接入复核0913

本记录对应网页绘图恢复后的工程接续。新增原图仍由主任务统一核验、下载与登记；本文不代表全部动作已经制作完成，也不解除完整比赛覆盖门槛。

## 已修复的接入问题

- **胜利动作停在第一张。** 原渲染把所有演出覆盖参数当作静态姿势，因此即使 `win` 有多帧也只显示第0帧。现支持显式 `{ anim, stateFrame }`，比赛胜利使用回合演出逻辑帧推进；暂停和重复绘制不推进，非循环动作停在末帧。`?hold=win/2` 等静帧检查方式保留。
- **其他分页可以盖住正确映射。** 原加载器核验了声明页上的帧，但随后遍历全部分页安装映射；误放在第二页的同名帧可能覆盖第一页。现先检查所有图集条目是否已声明、页归属是否正确，完整通过后才安装新纹理；失败明确报错，修复文件后可正常重试。
- **大跳、小跳错误共用固定跳姿切换时刻。** 两者在核心中的初速度不同，固定 `exposures` 无法同时对齐上升、顶点和下降。现增加可选 `airbornePhases`，只允许跳跃状态声明，直接读当前垂直速度选择已存在的姿势。没有配置的旧素材保持原有取帧方式。

所有修改限于渲染、资源校验、确定性素材打包和覆盖报告，不改变战斗状态、伤害、范围、时长、速度或重力。`src/core/FightSim.ts` 的SHA256保持 `7d4331cd1c8f76bc5eeebbb2db3e04ea49fccf8b04da59fce6da0ad8bcb6bd46`。

## 新跳姿作者格式

二姿素材：

```json
"airbornePhases": { "rising": 0, "falling": 1 }
```

三姿素材：

```json
"airbornePhases": {
  "rising": 0,
  "apex": { "frame": 1, "maxSpeed": 1 },
  "falling": 2
}
```

- 只用于 `jump_neutral`、`jump_fwd`、`jump_back`。索引对应各动作的 `frames`；必须是合法、不同的真实姿势。不能通过该字段改变攻击的真实播放节奏。
- 没有 `apex` 时，当前 `vy < 0` 取上升、否则取下降。有 `apex` 时，速度绝对值不超过 `maxSpeed` 先取顶点。
- `maxSpeed` 单位为世界像素/逻辑帧，和画布倍率、纹理密度无关。内部只把核心的整数子像素速度换算比较，不改核心数值。
- 原 `exposures` 继续显式保留；打包器和覆盖核查同时验证新增字段，并记录到覆盖JSON。
- 跳姿使用虚拟站立基线作为根点。收腿时最下面的鞋不是新的世界脚根，不能因裁切改变实际身体高度。
- 后撤步在当前核心中仍是地面状态，用自身固定逻辑时长的 `exposures`，不配置跳跃分相。

## KO前提核查

当前核心没有“生命为零立即在空中显示地面KO”的流程：地面受致死攻击时先进入 `hit_air` 并起飞；落地且生命为零才进入 `ko`。已用真实走近、实际轻拳接触和1HP受击夹具跑到落地，确认空中显示受击动画、落地显示KO末姿。因此没有新增无必要的 `airborneAnimation` 或修改核心流程。角色素材仍须分别提供合法的击飞姿势与地面KO姿势。

## 样板输入随真实素材扩展

进一步核对发现，旧样板永久屏蔽Up/B/D与双击方向，只承认轻拳、路飞重拳和大喷火；即使新图合并，起跳、翻滚和新招式也无法操作。现在从已校验运行清单和双方反应素材推导：

| 输入能力 | 开放依赖 |
|---|---|
| 跳跃（含小跳） | 自身起跳、三方向跳、落地，以及空中受击、倒地、起身全部存在 |
| 冲刺、后撤步 | 分别具有自身dash、backdash；一项缺失不关闭另一项 |
| 前滚、后滚 | 分别具有roll_fwd、roll_back；仅在对应方向允许AB组合 |
| 新地面拳脚/技能 | 真实出招动作已经声明；会击飞的招式还要求对手具备完整空中受击恢复链 |
| 空中拳脚 | 出招动作与自身完整跳跃、落地、空中受击链全部存在 |
| 投技、拆投 | 出招和连接成功双时序，对手被投/击飞恢复；可拆投另需双方throw_tech |
| 投射物 | 出招存在且双方具备所需反应，施放者也能承受之后可能发生的弹反 |

新招不再需要编辑逐招白名单。只筛选原有MoveData对象，没有改它的伤害、时序、判定或物理。对手素材缺口只关闭对应已绘制技能，原因放在诊断页；**已经声明却损坏的任何帧仍使样板入口报错，不能通过关闭能力掩盖损坏。** 控制提示和F11出招表跟随实际开放的输入/招式。完整比赛门槛继续独立执行。

样板默认仍由F5控制木桩；如需操作P2，切到“人控”。未制作动作不会因为选择人控而开放。诊断页新增 `sampleCapabilities`，可直接核对双方实际开放项。
