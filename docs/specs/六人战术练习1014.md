## 1. 范围、事实与取舍

- 【当前事实】基础教程有移动、轻拳、重拳、防御、Skill1、短连段六步；`TutorialProgress`依据本帧真实事件推进。原`Dummy`模式保持；本轮独立`RolePracticeSession`已加入下文的定时路线、指定输入和战术进度，不把它们塞入普通木桩随机模式。
- 【目标】每角色三条可单独进入、重试、跳过的练习；每条只完成一个明确战术结果。九技能、招式数值、伤害、判定、费用及原战斗输入资格保持。
- 【设计初值】下文开局距离、脚本等待、位移门槛、观察时限是训练设计初值，**已通过一次真实sim可达性检查，尚未据真人操作校准**。后续先改训练站位/脚本节拍解决实际可达性，记录前后值；不能为练习通过改旧招式或直接移动战斗中的木桩。
- 不强制每招依次完成“命中、被防、落空”三关。必做结果见18条合同；反例用于定向实现测试或玩家主动点开的演示，不阻断下一练习、自由对局和普通比赛。
- “形成威胁”“认识风险”“打法成立”仅可作为说明，不能写进成功布尔条件。代理完成木桩练习也不能代表真人理解或好玩。

## 2. 共用执行约定

### 2.1 身份、坐标与开局

本表玩家为P1（索引0），木桩为P2（索引1）。默认P1朝右、P2朝左；双方根点距离为 `d` 像素，放在舞台中场 `P1.x=-d/2`、`P2.x=d/2`，不是墙角。`o`为本次开局P1根点，`s=1`为其初始朝向；镜像时全部位置按 `o+s×偏移` 定义，方向输入取角色实际朝向，不写死Left/Right。内部坐标统一 `px()` 转为子像素。

进入/重试是明确的训练设置：创建或完整重置练习模拟，双方在地面 `y=0`、`airborne=false`、`idle`，满血、气0、无强化/疲劳/灼烧/硬直/连段/残留投关系/道具/输入历史与缓冲；`phase='fight'`、无限回合时间。18条均不需无限气。训练无限血只供恢复，不作命中依据；重试明确恢复满血。角色资源仍走已有真实入场校验，缺资源显示原因，不用替身或色块放行。

说明面板可暂停模拟；玩家确认“开始”后令本次 `t=0`，脚本按**实际推进的fight逻辑tick**计时。暂停/慢放等待不消耗脚本，逐帧实际推进一次算一tick。每次重试新建attempt序号，旧事件、旧进度和旧脚本阶段不得串入。普通F6重置在战术练习中等同重试当前条目。

每条最多观察600个fight tick（设计初值）；本条已指定结果成立立即成功并停止脚本，不必等完。超时显示具体提示和“重试／下一条／自由练习／返回”。成功不自动替玩家出下一招。受击、走错、放错招可提示；只有破坏本条条件时才终止本次尝试。切换木桩模式会退出受控尝试并回普通自由训练，不能继续累计本条完成。

### 2.2 合法输入脚本记法

木桩控制器只读当前世界、只返回位图，交给原 `sim.step({p1,p2})`；木桩固定经典模式，P1沿玩家选择的经典/一键模式。禁止直接调用 `startMove`、设置战斗中位置、airborne、命中或强制扣血。

| 记法 | 每tick具体输入与结束方式 |
|---|---|
| `0` | 无输入；不会自动格挡、靠近或补招。 |
| `F/B` | 按当前朝向的前/后绝对方向位。只用单次持续行走，不用方向脉冲触发冲刺。 |
| `蹲防` | 每tick `Down\|B`；不追加攻击或拆投。 |
| `236A` | 每tick依次 `Down`、`Down\|F`、`F\|A`、`0`；之后0。 |
| `214A` | 每tick依次 `Down`、`Down\|B`、`B\|A`、`0`；之后0。 |
| `236B` | 每tick依次 `Down`、`Down\|F`、`F\|B`、`0`；之后0。 |
| `短跳入` | 单tick `Up\|F`，随后持续0。预跳中松Up，由原core产生向前小跳；不直接设置起跳或空中速度。 |
| `路线(a→b)` | 开局根点为 `o+s×a`；到表定时刻开始持续F，到实际根点首次达到/越过 `o+s×b` 后持续0。位置只由正常行走产生，目标是固定开局锚点，不跟踪玩家的新位置。被命中/抓住时停止后续脚本输入。 |

P1的指定招显示**实际当前绑定**：普通 `st_c`显示普通重拳键；特殊技一键显示对应Skill槽，经典显示真实指令和拳/脚键。未绑定给设置入口，不硬编码Q/E/R；改键后立即刷新。出招表和玩法卡引用同一角色目标数据。

### 2.3 事件与最小接触前态

`H(m)`：本attempt开始后，本step新产生 `kind='hit'`、`attacker=0`、`defender=1`、`moveId=m`、`damage>0` 的真实 `HitEvent`。它不包含block、armor、burn、tech、clash、reflect，也不能用 `hasHit`、动画、输入、血条差或 `moveId`出现替代。表中要求道具时再加 `projectile=true`；近身时加false。无额外要求时，一条H已经足够。

少数目标需要区分**被打飞前就已在空中**和**这次攻击把人打飞**，或区分**抓收招**和**打中中立**。现有HitEvent没有这些前态，不能用step后的`hit_air`或`counter=false`猜测。实现只需为真实命中事件添加一个可选值快照，例如：

```ts
defenderBefore?: {
  state: StateId;
  moveId: string | null;
  stateFrame: number;
  airborne: boolean;
}
```

在该次命中结算改变对手状态/招式/airborne之前取得不可变值；不得引用会变化的FighterState。近战与道具命中保持同一含义；并发接触不能拿本次已写入的受击状态当其前态。它是原HitEvent的附加观察信息，不增加新事件类型、整局轨迹、持久日志或第二套战斗状态机。旧事件消费者不依赖这个可选字段；缺字段的历史事件不能满足需要前态的新练习。

`收招(m,k)`按当前锁定招式表计算：`L`为最后一个带攻击框FrameData结束的累计tick，`T`为总时长；要求前态 `state='attack' && moveId=m && L<=stateFrame<T`。中间两段之间无攻击框的启动不算收招。不能把当前帧没有hitbox或counter=false单独当成收招。

抓取条目用已有`throw`连接事件，再等待同attempt、同一连续招式实例的释放`hit`；不用新增抓取系统。实例号从当前角色状态本地锁存，木桩每attempt只出一次指定招，未要求HitEvent新增实例字段。练习控制器只保存本次必要的几个标记、帧号和距离，重试即清空。
