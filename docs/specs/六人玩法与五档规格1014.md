## 1. 数据单位与兼容基线

- 逻辑60tick/秒。1像素=256子像素，`px(x)=round(x×256)`；位置和速度状态用子像素整数。世界y=0为地面，负方向向上。
- 配置判定框是面向右、相对脚下根点的像素`[x,y,w,h]`。左向x镜像为`-x-w`，随后乘256并加根点；严格矩形交叠才接触，边线相等不算重叠。
- 帧持续、硬直、消耗及倍率分子/分母为整数。倍率使用`floor(value×num/den)`。快照中的`FrameData.velocity`与击退速度为像素/tick，`movement`字段为已经转换的子像素/tick；不能再重复转换movement。
- 当前按键位0—17与九个技能槽保留；新觉醒使用未占用位（建议`1<<18`），不能重排旧位。旧输入、旧数据与未开启五档的行为按快照保持。
- 当前六人共157招、54个快捷槽。快照含每招每帧判定/时长/伤害/硬直/消耗/指令以及AI配置，是精确现值资料；未来新五档表单独保存，不能覆盖此历史快照。

## 2. 普通入口与六人放行

目标：无需开发参数即可进入已验收六人完成包；开发中的新形态不混成成品。

- 无`art`参数：在游戏模块初始化前补`art=anime`；缺`scope`才补`full`，缺`quality`才补`high`。保留其它已有查询参数。
- 已有`art=legacy`或`art=anime`不改写；显式`scope=sample`、`quality=performance`保留。无参数与显式完整模式从标题开始。
- `--full`本地启动器根请求同样补明确动漫参数；`--no-open`启动仅打印网址，不打开Edge/系统默认浏览器。
- 正式六人登记需绑定实际UI/身体/技能/声音与完整模式依赖。仅目录存在、图数达到、DEV可进入不能直接设置放行标志。
- 路飞五档属于同一个选人槽。**仅新六人完成包的`anime/full`路径**启用五档及其资源门禁；选中路飞时，本场预载其常态与五档所需资源，进入战斗前校验；未选路飞不下载五档大包。加载失败显示具体失败/重试/返回，不静默禁用五档或借常态图冒充。显式`art=legacy`、样板路径和冻结`v1/v2`保留旧能力与依赖，不因新增五档强制下载新素材。开发逻辑候选可单独启用并明确标为未完成，不替代正式包门禁。
- 来源记录必须写实际服务脚本、D盘根、完整URL和构建/资源版本；不能把C盘独立副本或旧公开四角认成当前候选。

验收例：裸`/`显示动漫标题；`/?art=legacy`仍旧版；`/?scope=sample&quality=performance`补art但保留两参数；缺五档必须图页时六人完成包的路飞比赛阻止启动并可重试。

当前实现：`index.html`→`bootstrap.ts`→纯入口规范化→动态import main，确保静态依赖初次读取URL前已补默认。4344裸根IAB已实见；生产角色登记仍四角，六人正式登记及五档完整资源门禁尚未完成。

## 3. 角色玩法卡与三招教学

六人的具体招式ID、主要赢法和弱点见全局规划第3节。显示内容从一份角色玩法数据读取；选人、出招表和教学不得各自手写不同名字/键位。新角色不通过多加一句形容词冒称打法已成立。

### 3.1 选人卡

输入为角色ID、当前操作模式、当前键位。输出：名字/形象、一句话赢法、三条“键位＋招名＋使用时机”、一个明确弱点。更改键位后立即更新，不能固定写Q/E/R；含普通攻击的核心选择显示其真实普通键。光标移动只播菜单音，锁定角色才播一次选人回应。资源未就绪有加载状态；取消回到可选择状态，不锁死。

### 3.2 教学入口与状态

保留已有基础六步引导与完成记录。每角增加“学会这三招”，从选人提示或训练菜单进入，普通比赛可跳过教学直接进入。

新练习状态：未开始→说明目标→真实操作→事件校验→结果反馈→下一练习/自由训练。失败给可行动提示，允许重试或退出，不自动替玩家出招。木桩只产生合法InputFrame；练习的开局重置明确属于训练设置，不伪装自然对局。

逐项可执行合同见[六人战术练习1014](六人战术练习1014.md)：包含稳定ID、开局位置/条件、木桩合法输入、通过事件及必要前态、失败/重试。下方是意图说明，不直接用“形成威胁”“认识风险”等抽象词判断通过。成功只要求该关明确的战术结果，反例可用于测试或可选演示，不增加每招三遍的强制教学流程。

- 成功由当前练习开始后的事件判断，历史命中不计、空挥不算命中。
- 路飞：伸长拳在可达距离命中；突进接近并认识防住后的风险；成功反射明确远程道具。
- 赤犬：用犬弹形成路线威胁；大喷火命中与落空后被反击有不同结果；抓取练习明确进入实际抓取范围。
- LABUBU：短扑接近；连拍完成有效接触；抓防守对手，同时演示范围外抓空。
- 星星人：星弹试探；落星命中设定落区内移动木桩、对手离开可避；推开后距离实际拉开。
- 青雉：冰矛命中路线；冰脊命中预测位置而非追踪目标；上挑命中跳入木桩，地面诱出能落空。
- 香克斯：刀距试探；对手长招挥空后在恢复窗口用突刺命中；上斩截跳，不能把不存在的架刀反制当目标。
- 五档追加：有资源开启→使用五档核心招→理解到期/疲劳与对手反击机会；不能靠教学跳过形态资格。

新完成记录建议独立`opf.roleTutorial.v1`：`{version:1, completed:{角色ID:[稳定练习ID]}}`。成功后才增加ID，重复通过幂等；损坏/存储拒绝按本会话继续，不清除旧基础教程键。旧`opf.tutorial.v3`、`opf.tutorial.simple.v1`保持。

验收例：香克斯空挥突刺不完成“抓收招”；木桩已结束收招才命中提示时机不符；修改轻拳键后卡片/教程均显示新键；完成记录不可用时仍可玩普通CPU。

当前实现：18条均有真实FightSim输入正例。训练/选人F2打开三招目录，说明菜单暂停模拟；运行中可重试/下一条/自由训练/新建简单CPU。根IAB通过路飞第一条、星星人第二条、青雉第三条三个代表，分关勾选可见，未穷举18条浏览器或宣称真人理解。旧F2同时翻出帧面板的缺陷已修为Shift+F2调试、普通F2教学；根在最终合并包复验选人/Fight普通F2只有目录、无底部调试字，通过。

## 4. 路飞五档状态合同

### 4.1 输入与资格

【确认】消耗资源、限时五档、结束疲劳；保留二档/三档，四档延期。五档不占第七个人物槽，不要求逐档升级。

【设计初值】新动作“觉醒”：P1默认T、P2默认PageUp，标准手柄默认LT（现有4/5肩键和Start不变）；键盘可重绑，经典/一键模式均可使用。绑定冲突必须显示原占用并拒绝保存，不覆盖用户已有键。手柄配置可实现，但未取得真手柄证据时注明待实测。

输入存储建议独立`opf.awakening.v1`：`{version:1, bindings:{p1:键码或null,p2:键码或null}}`。不存在时使用空闲默认键；默认键若被用户旧配置占用则保持未绑定并提示设置。损坏内容只回退本会话有效值，不主动改写旧`opf.keys.v1`/`opf.keys.simple.v2`。保存新绑定仍验证与当前双方操作模式全部键位冲突。

一次按下边沿提出一次请求，短于一逻辑tick也须锁存；长按不会连续提出。与普通攻击/技能新按下同一tick时先走原攻击选择，本次觉醒忽略且不排队。

全部资格同时满足才接受：当前为fight、角色路飞、地面可操作中立状态（idle/walk_fwd/walk_back/crouch）、无现存强化、无疲劳、气≥300、对应完整资源已由入场阶段校验。攻击收招、受击/防御硬直、投/受投、起跳/空中、KO与暂停均不能接受。

失败不扣气、不切形态、不启动任何计时、不缓存等待将来满足；HUD说明资源不足/空中/动作未结束/强化或疲劳中等原因。其它五个角色收到觉醒输入不产生行为。

当前实现接口：`Btn.Awakening=1<<18`；`FightSimOptions.gear5Enabled`默认为双方false，只有真实资源资格或明确逻辑样板才能传true。`awakeningAvailability`与`awakeningFeedback`提供逻辑原因；完整HUD和资源门禁未接。设置两模式都能改独立觉醒键，冲突拒绝/解除/保存已实现，IAB实际拒绝J/L并成功H后恢复T。**当前正式路径全关，设置显示“觉醒（尚未开放）”且说明按键/手柄LT不会变身；最终IAB实见并reload确认仍T，不能因绑定存在声称五档可玩。**

### 4.2 启动、持续和结束

| 状态 | 行为与转移 |
|---|---|
| 常态 | 现有招式、二档、三档技能与全部基础数据保持 |
| 觉醒启动 | 接受即扣300，24tick启动，无额外无敌/霸体/回血；尚未提交形态前可被打断 |
| 启动被打断 | 取消待生效觉醒，费用不退，不进入五档、不另加疲劳；走真实受击/投技后续 |
| 五档提交 | 启动完整24tick后切到真正五档，remaining=720；启动动作尚有12tick收势，新形态受击图需可用 |
| 五档有效 | 计时按fight逻辑tick递减，含打击定格；暂停/非战斗不计。移动倍率6/5，通用伤害倍率1/1，通用启动跳帧0；优势由独有招式与节奏体现 |
| 到期待退出 | remaining=0后不准启动/取消进入新的五档招式；完成当前出招、抓投/受投、受击、空中落地等安全收束。原招式版本、判定、时序和抓点不在中途改成常态 |
| 疲劳 | 安全退出后回常态，180tick；移速倍率3/4，可正常普通攻击/防守/跳跃，不扣血；期间二档和五档都不可开启 |
| 疲劳结束 | 回常态全部资格；重新积够资源后可再次觉醒，不设置隐藏的单回合一次限制 |
| 回合结束/KO | 战斗计时冻结，最终形态用于本回合胜负演出，不再开启新能力。下一回合、重赛、换角清理形态/待退出/待生效/疲劳和旧声效状态 |

启动按**动作tick**计算：接受请求的帧N创建启动计数0，随后24个未被hitstop冻结的动作tick才走完启动；因此没有冻结时在N+24结算后提交，存在冻结时顺延。最后一个启动tick先完成真实受击/抓取碰撞结算，仍处于有效启动才提交；同tick命中/被投优先打断。提交tick不扣720，随后完整720个fight tick（含hitstop，不含暂停/非fight）计完才进入待退出。12tick收势从提交后的动作tick开始，遵守动作冻结。

到期后不允许新普通技、技能、跳跃、冲撤、翻滚、普通投或任何主动取消。保留当前动作的推进、已有强制反应及合法防御输入；首次到达`idle/walk_fwd/walk_back/crouch`任一安全状态时，**先退出形态，再处理该tick的新动作输入**。落地/收招/受击恢复都按这一顺序处理，不能靠同tick再跳或接招延长。正在抓/受投则等双方关系解除，仍保持原动作/形态版本。KO/回合结束优先保留最终形态演出，下回合清理。安全边界可能使视觉收束晚于名义12秒，UI显示“收势中”，不能把到期后的剩余动作当成可无限延长的五档。

当前实现疲劳读取第一个install的参数；新增形态必须记录或准确解析疲劳来源。五档疲劳不能误用二档的90tick/4÷5移速；没有觉醒输入的旧二档10秒、13÷10移速、23÷20伤害、90tick疲劳等按快照保持。

“二档和五档都不可开启”的约束只针对**五档来源疲劳**。原二档来源疲劳中能否再开二档保持现有行为；觉醒本身在任何疲劳中都不可接受。五档安全退出当tick设置180且不立即扣减；随后180个fight tick计完清疲劳来源，期间暂停/非fight不计。下一回合/整场重赛同时清来源、剩余tick和待生效状态。回合重置继续保留旧规则中的气槽；整场重赛重新创建比赛才清气，五档不会自行更改此继承规则。

## 5. 声音、反馈与缓存

### 5.1 日常台词开关

默认正常移动/待机不触发人物台词；脚步、衣物与运动音效继续。设置新增“角色闲聊”开关，用户开启后沿原限频规则触发。现有已采用文件和来源保留，不删除LABUBU/星星人已确认声线。

在现有`opf.audio.v1`配置增加可选`characterChatter:boolean`，旧配置缺字段时本会话默认false，原静音/总音量/分组音量保留，用户保存设置才持久化。禁用只停止/取消日常声，不中断选择、攻击、受击、KO与胜利回应。

当前已实现：引擎读取缺字段不写回；`setCharacterChatter`等明确设置操作保存。`DailyAudio.step`第5参数默认false，关闭时不产生日常台词且不积累旧闲置触发债务，运动SFX仍产生；引擎再精确阻止/停止`voice.<id>.idle/move`。根IAB看到默认关闭→开启→关闭，原分组音量不变；此项UI证据不代表真人听感。

### 5.2 事件优先级

同一角色同一时刻最多一条人声。目标优先关系：KO/胜利结果→受击→重要技能/觉醒→普通出力→可选闲聊。由现有引擎优先级机制映射，不另造队列；低优先级冲突直接丢弃，不能数秒后补播。系统播报独立限并发并为人物声留可辨识空间；音乐沿已有压低与恢复机制。

当前运行映射：KO/win100、hurt85、技能/选择70、effort50、idle10、move9。沿现有按玩家单声和分组并发机制，不新增延后重播队列；系统播报仍沿现有分组限制。来源台账/音频不因运行优先级改写，青雉win保持1013保音高短版。上述优先级、停止范围和丢弃行为有定向引擎证据，尚未取得本轮真实扬声器/真人听感。

普通攻击使用少量短音并限频，不要求每击台词。新片的实际完整时长须适配触发到下一次清声窗口；现有胜利窗口名义110/60秒。青雉当前胜利已采用重新听核的1.720791667秒文件，旧2.40秒仅闲聊使用，不能重建错回长版本。

选人锁定→对应文件一次；重赛/换角→停止旧非循环声音/字幕；静音/暂停/浏览器未解锁→显示状态，不用无声宣称播放成功；文件失败可重试，关键配音不能静默合成另一演员。

### 5.3 加载

菜单只取轻量界面；按实际参战角色预取。五档资源与路飞共用内容哈希/格式选择/下载去重/缓存校验机制；资源缺损或版本不一致不能混用旧帧。重赛复用校验后的资源，换角只补新增依赖。

本轮实际测新增五档参战组合的菜单与首拳、同页重赛和一次失败恢复。旧基线可复用，不在无改动时重跑长时全量性能；性能目标沿项目既有规则，未达到如实记录而非调低纹理质量掩盖。
