# Jev / Jev-cu 接入评估0922

查阅日期：2026-09-22（北京时间）。项目：One Piece Fighter；源码基线：`3892924c85a13ecc938ffe9da1a955c115090746`。本轮只调研与规划，不代表实施批准。

## 总体判断

**【推断｜高确定性】目前不应把 Jev 放进游戏运行时，也不值得为这款游戏直接安装 Jev-cu。** 当前真正影响玩家体验的是首场加载、角色差异、CPU 攻防与界面呈现；这些问题已有明确的代码、资源和试玩改进路径。接入外部决策模型会新增联网、密钥、时延、费用与不可复现因素，尚无对应收益证据。

**【推断｜中确定性】目前没有证据充分、应立即启动接入的优先模块。** 只保留一个有条件的候选试验：用 Jev 辅助核对“验收主张是否被材料支持”。先在本地确认是否持续存在规则无法覆盖的真实含混案例及复核耗时，再决定是否试验；当前列出的典型反例，大多已能靠规则识别，不能据此证明模型价值。条件成立后，它也只给复核建议，不决定验收通过、素材采用或发布；与普通规则、检索加人工、现有大模型结构化输出对照，没有净收益就停止。

**【事实】本轮未调用 Jev 真实接口，未安装 SDK 或 Jev-cu，未发送项目数据给 TypeSafe，未执行 Jev-cu 界面操作，未重跑游戏测试。** 下文游戏成绩来自本轮读到的既有验收记录，不是新测试结果；API准确性、实际费用、国内时延和 Windows 端到端均为“未实测”。

### 结构化回答不等于业务正确

- **Choice**：最多255个有限选项；返回所选项、各项概率及confidence。必须提供“材料不足/不适用”，不能逼它从错误选项里选一个。
- **Score**：2–10个有顺序、有文字定义的等级；返回概率加权分数，可落在两个等级之间。它不是精确计算器，也不能用插值还原伤害、帧数或时延。
- **Noul**：对是/否问题返回0–1的yes概率；当前接口**没有独立confidence字段**。
- **confidence**：Choice/Score概率分布的派生统计量，不是另一个独立校验器，也不能直接解释为“90%一定正确”。三者门槛不能互搬。
- **输入**：当前文本限定，支持字符串或JSON对象/数组；不直接收图片、音频、视频。总请求64k token，state加最长单题不超过32k。中文和日文可输入，但官方说明英语训练占主导，CJK准确性需要自行测试。
- **官方已承认的弱点**：精确数学/计数/日期比较、多跳推理、无关长上下文、对抗文本和文字生成。博客“不能幻觉”的保证针对输出类型/结构，不能推导出选项一定符合事实；MCA亦明确输出可能错误。[S1–S4,S10]

### 时延、费用与数据边界

【事实】官方当前价为每百万输入token **US$0.042**，输出免费；公布限额250,000 token/s、1,200请求/min且注明会动态调整。博客70–500ms和大幅提速降本属于厂商测评，主要从美国西海岸访问；部分评估以其他大模型平均输出为参照，并非本游戏的人类金标准。博客Doom演示也使用文本化状态，作者承认非AI bot可以玩得更好。[S1,S2]

【事实】官方承诺不以客户请求/响应训练模型；隐私政策明确美国托管与处理，一般保留期不是默认零保留，企业ZDR需要另行确认。MCA与DPA仍约束存储、处理、服务提供商及用途；不能把“SDK本地运行”“不用数据训练”写成“数据不出本机”。当前账户资格、实际限额、所适用合同与ZDR均【不知道】。本轮没有打开账户控制台或读取key。[S10]

## 4. 有条件的候选试验：验收主张与证据核对

本轮零项立即接入建议。以下方案只有在真实含混案例和复核负担得到确认后才进入“值得优先验证”。这是开发工具，不随游戏发布，不是自动验收器。建议未来确认后放独立Node脚本；先在既有`docs/`记录规则，试验结果按项目约定放新的本地验收目录，创建时先写结构说明，保留每次样本、版本和报告，不覆盖旧记录。本轮不创建该工具或目录。

### 输入与有限输出

本地程序先从指定文件抽取一条主张和最少的相关证据；算术、日期、版本/哈希、退出码与字段完整性由代码核验。发往Jev的拟定字段仅为：

`claim_text`、`evidence_excerpt`、`evidence_kind`、`scope_flags`、`verified_facts`、匿名`sample_id`。不发整仓库、整段会话、原图、录音、浏览器资料、用户名绝对路径、凭证或未获准的项目文本。未来调用前提供实际样本白名单与可审查的请求正文；脱敏后仍属项目数据，仍需本轮后续明确批准外发。

把一个大判断拆为小问题：

1. Choice：主张要求哪类证明？`engineering / controlled_runtime / actual_network / visual_audio / human_replay / mixed_or_unclear`。
2. Choice：给定证据对该单条主张的关系？`supports / limited_scope / contradicts / insufficient`。
3. Noul：主张是否把有限条件扩大到了未测人群、设备或线路？保留yes概率；它没有confidence。
4. 必要时Choice：从本地已定位的证据段ID中选依据，包含`none`。模型不生成文件路径或引文。

互相独立的问题同请求提交；依赖前项的后续判断由代码择需调用，不假装一批并行问题已经读取了彼此答案。字段名只供程序索引，官方说明question ID不参与推理，语义必须写进instructions/criteria。

代码组合输出仅为`review_scope / review_conflict / collect_evidence / no_issue_detected`，附原始段落链接和固定提示语。`no_issue_detected`只表示未发现问题，不代表放行。已有硬门禁失败、未听辨字段、不同构建或不同测试条件，均不能被模型“支持”覆盖。Score不作为初版必需项，避免无依据加权成一个总质量分。

### 低置信度、故障与完成核验

- 不照抄通用0.5/0.9阈值。小样本阶段只记录完整概率分布，所有输出仍需人工复核，不宣称已完成校准。只有真实样本足够、按类别分层留出验证后才选择门槛；低把握、`insufficient`、问题间矛盾、拒答或响应不合法均转人工。Noul单独评估，不借用Choice confidence阈值。
- 【拟定试验参数】每请求5秒、单样本总预算8秒，最多一次429/5xx重试且受剩余预算约束；401/403/422直接停止该批模型调用。网络错误保留未完成样本，不无限重发。超时不写“通过”。这些是待批准的试验设置，不是现有实现或实测SLA。
- 固定`jev-1.13.0`并记录响应实际model、问题版本、证据哈希、usage、全部尝试时延与失败。模型变更要重新校准；不默默改到其他供应商。人工或现有核对流程接管时单独计数，不算Jev成功。
- 完成判据：输入样本数与输出/失败/待复核数守恒；样本ID、证据版本匹配；结果可回到原文；评审人按预先答案确认关系。模型完成概率不参与完成判定。
- 不改变四项工程检查、完整比赛、18招真实输入、经典回放、720p/1080p、带声对照、15分钟前台和既定网络目标，也不降低真人试听/复玩标准。

## 5. 最小对照验证与投入停止条件

以下全部是**待批准的方案与验收目标，未实测**。这轮不为展示效果调用任何模型。

1. **先确认需求，再建立规则基线和金标准。** 先从0913、0915、0922真实记录整理规则无法解决的案例及实际复核用时；若找不到持续的含混案例，到此停止，不启动API试验。条件成立后，初轮最多60条（20条完善规则与问题定义、40条锁定冒烟检查），不为凑数量改写同一问题。覆盖当前/历史版本、成功/失败、中断、受控/公网、声音/画面/复玩。真实摘录与人工反例分列；同一事件及其改写归到同一分组，不能跨设计/检查集。样本只读原材料，保留引用和版本；预先双人标注或独立复核，争议保留“证据不足”。未完成标注前不能报告模型准确率。60条只用于初筛和发现错误，不能支撑多类别概率校准结论。
2. **先看规则是否已足够。** 与四条路径比较：错误码/字段/明确关键词规则；检索定位+人工复核；现有可用大模型的原生结构化输出；相同输入的Jev。规则已解决的例子不记为Jev新增价值。若使用System One Adapter作补充公平对照，需单列其概率输出和纠错重试成本；不能故意让LLM做更重任务再宣称Jev节省。新付费LLM对照同样需要批准。
3. **再批准有限真实调用。** 先给出样本正文、发送范围、供应商、模型及总支出上限，再执行。预算按实际`input_tokens × 当日单价`统计，加上失败/重试、对照模型、人工标注、复核和维护成本；目前不能计算真实ROI。现有Codex使用额度不等同于另一个供应商API额度。
4. **同机测端到端。** 记录从本机准备好输入到有效结果的P50/P95/最大耗时，单列网络/服务/重试；在Windows原生PowerShell+UTF-8下跑中文与中日英混合样本。对照保持相同证据与问题，避免翻译修正被算成Jev增益。若另测英译版，翻译成本与语义变化单列。
5. **故障和接管。** 经批准后注入本地mock的401、429、超时、断网、缺字段和版本不符，验证保留样本、停止重试、转人工与可恢复性；这些只能证明故障处理代码，不能冒充真实服务稳定性。实际接口故障率另记。

| 维度 | 如何验收 / 继续条件（拟定） | 停止或不扩大的条件 |
|---|---|---|
| 判断正确性 | 小样本逐例报告正确/错误/弃答、严重假支持和分母，与规则及现有LLM配对比较；不把稀少类别的比例当稳定准确率 | 严重假支持必须单列；若不能在不增加严重错误的前提下减少复核量，停止 |
| 概率是否可信 | 初轮只保存概率、confidence及逐例答案，观察是否有高把握错误；若初筛有价值，先定义可容忍误判率，再据置信区间与类别覆盖设计更大独立样本，计算可靠性分桶/Brier score及弃答覆盖，Noul单独评估 | 样本不足就明确“未完成校准”，不按小样本分桶设置自动决策门槛；高confidence重复严重误判则停止 |
| 小试点放行 | 锁定测试中严重假支持为0，人工复核后结论不劣于基线；该“0”仅是有限样本结果 | 有严重假支持时保留失败案例，最多修一次问题定义后用新留出样本复查；仍出现则停止该方向 |
| 净效率 | 【拟定目标】包含准备、调用、纠错、人工接管的同等质量总处理时间，比现有最佳路径减少至少20%；有效响应P95≤2秒 | 仅API很快、总人工时间不降；材料量太小，节省不足抵维护成本 |
| 费用 | 每条有效且复核正确的结果成本；所有请求、重试与人工成本计入；不超过批准上限 | 规则即可处理，或低价被额外标注/修错抵消；达到预算即停，不加码 |
| 恢复与完整性 | 每条样本有结果或明确待处理状态，重跑不丢失、不重复提交人工结论，故障全部可回到原流程 | 超时被写成通过、记录丢失、重复计成功、私自切供应商或多发数据 |

小试点的“通过”只表示值得收集更多真实旁路证据，不能证明低误放率、长期校准或普适准确性。即使零次严重错误，也应说明样本有限。后续仍只做旁路复核；没有足够实际使用量、独立验证样本和可观测收益，不升级成自动化平台。

## 6. Jev-cu 为什么暂缓，以及未来怎样证明它有用

### 当前源码与本机之间的差距

【事实】Jev-cu运行说明主要覆盖macOS App AX（辅助功能文字树）；浏览器批量判断仍被列为未验证实验。它通过`cua.getApp()`包装App driver；本会话工具明确原生电脑API禁用、提供浏览器入口，因此不能直接照其macOS示例运行。Node脚本在Windows可解析CRLF，不等于Windows原生App或Codex内置浏览器端到端兼容。[S11]

【事实】游戏主要按钮/人物由Phaser在Canvas绘制，诊断窗口虽有DOM文字，`DiagnosticsPanel.snapshot()`也能输出结构化状态，但不自动使游戏所有可交互目标出现在AX树里。Jev-cu候选不足时只会重取完整树后升级接管；画布点击/拖拽坐标依赖宿主planner，不是Jev看图定位。这轮没有执行新的界面观测，所以具体可见控件数量【不知道】。已经有可读取的状态时，普通脚本通常可以直接选择确定动作，无需再调用Jev。

【事实】源码值得保留的设计是：执行前校验目标仍在本轮候选中、使用未截断label重做策略检查，每步操作后重新观测，提供`verify`接口。但不能把这些理解成完备的安全与验收机制：

- `policy.mjs:27–36`默认done≥0.9、risk≥0.2要求确认、普通confidence<0.5升级、<0.3停止，对部分App放宽到0.4。它们没有在本游戏上校准；将Calendar/TextEdit/Figma称为“零副作用”也不适用于所有操作。
- `loop.mjs:294–299`在未提供`verify`且无子目标差异时，可以按模型判断直接返回done。项目适配必须强制独立核验，拒绝仅凭done计成功。
- Skill写“连续两次无效动作停止”，循环代码只记录`no change`与动作历史，未实现相应独立计数强停；需要宿主补足。
- `loop.mjs:344–360`可让`resources.at`坐标覆盖所选元素点击；坐标与被策略检查的label可能分离。若试验先禁用坐标/拖拽，仅操作允许的文字控件，并重新核对目标。
- 默认每次HTTP尝试超时60秒；429/5xx最多重试两次、退避1秒/3秒；网络抛错直接返回错误，没有备用模型/供应商。默认值不符合本项目小交互试验的等待预算。
- `confirm/escalate`是返回状态，实际用户确认、接管和权限仍由宿主负责。模型risk再低也不授权删除、配置/密钥修改、外发、安装或发布；保持本项目现行授权边界。

### 它会向外部发什么

`jev-decide.mjs`直接向TypeSafe发HTTP，当前默认`jev-latest`。实际state包含任务goal、app、上下文、候选、最近6条动作及constraints/planner plan；questions再次包含goal和候选描述。`buildContext()`取观测开头两行、前6条AX text与焦点行，最多1500字符；候选最多40条，每个描述删除URL、合并空白、截断至120字符。**当前代码不发截图，但这些文字可能包含用户名、聊天内容、窗口标题、表单值和本地路径；删URL不等于脱敏。** [S11]

若未来操作ChatGPT网页，必须限制到新建专用制作会话的必要控件，排除侧栏聊天历史、账号区、其他项目内容和未经批准的提示词/资料；先展示真正会发送的请求白名单。即使只是浏览公开游戏，模型调用也属于外部推理。宿主CU与Jev是两个处理通道，不能混同权限。

### 重新评估的最小路径（暂缓项，不列为本轮优先项）

先证明“单一页面存在足够可读文字控件、当前Windows浏览器driver可用、多个真实分支需要语义选择”，再谈接入。若这些条件不成立，到此停止；不为Jev-cu特意重做整套UI。

条件成立且用户另行批准后，只取低频页面流程的有限集合，如“设置页进入音频页、读到目标设置、返回原页”。输入只含本页允许控件、当前页/焦点、期望目标和最近动作；输出限`click_element / press_key / wait / ask_user`，参数由代码提供。把找页面、选控件、结果核验拆开；已知正确控件时直接CU。禁改账户、禁网页提交、禁真实素材上传、禁开始生产生成任务。

逐动作必须检查实际页/焦点/设置值，不用界面有变化当成功。操作结果不明先观测，不能盲目重放；失焦、目标消失、低把握或两次无进展立即交接。保持独立`verify`、步骤/总时间/费用上限和可读轨迹。

比较三种方法：固定脚本、现有宿主直接CU、宿主+Jev-cu。度量整条任务正确完成率、误操作、重试、人工接管、墙钟时间与总成本；同机器同起始状态重复，中文标签和布局变化分组。只在比现有最佳路径节省净时间、无新增严重误操作、全部结果可独立验证时继续。静态AX选择正确、dry-run或作者演示都不算本项目端到端成功。

## 7. 实施顺序与待确认条件

1. **游戏主线优先。** 后续版本先规划角色配置、按参战者组织人物/FX/语音依赖、选人布局与CPU复现；本评估不改变已批准范围，也不开始实施。
2. **先审查需求和规则基线，再决定是否试Jev。** 当前未知量是规则无法覆盖的真实案例、复核耗时与频次，而不是“能否返回JSON”。没有这项需求证据，所有接入候选继续暂缓；条件成立后只考虑第4–5节一个旁路试验。
3. **实际调用前再确认。** 需要可用的TypeSafe账户/key（不发在聊天或代码里）、本机连通性、脱敏后样本白名单、数据处理条件、批准费用上限及人工复核人。当前本机Node v24.15.0、Python 3.14.4满足文档最低版本，但包未安装、接口未实测；初版可只选Node路径。
4. **先影子对照，后决定是否维护。** 只有达到第5节条件才考虑常用工具；Jev-cu需另过Windows/浏览器适配与文字控件可观测性检查，不随Jev试验自动安装。

决策记录：不以Doom演示作为本游戏实时AI证据；不把普通代码可计算的规则交给模型；不把缺少试听/视觉证据的问题包装成评分问题；不照抄Jev-cu默认安全门槛。独立复核发现，现有示例大多规则可解，且初轮样本不足以支持校准结论，因此将“立即优先试验”收紧为“先验证需求、有条件再试”，避免分散角色与复玩升级的投入。
