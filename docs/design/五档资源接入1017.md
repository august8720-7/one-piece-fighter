## 加载与场景接口

从`src/render/assets.ts`导出：

- `loadAnimeCharacterForms(scene, ids, downloads?)`：由新的六人完整动漫路径显式调用；先加载常态，只有参战`luffy`请求`assets/characters/luffy/forms/gear5/runtime.json`。返回`AnimeLoadResult`，错误的`characterId`为`luffy:gear5`。镜像请求去重，重新载入使用独立任务键；错误移除该形态登记而保留常态资源。运行中已有presentation的对象不被原地删除。
- `isGear5AssetReady(scene, baseAsset)`：核对两包版本、常态36tick觉醒动画、完整五档规格、不同纹理身份和所有实际安装帧；任一缺失为false。只有通过此项及普通比赛原有资源门禁，集成层才能传`FightSimOptions.gear5Enabled[side]=true`。
- `animeCharacterPresentation(asset)`：把`asset.runtime`、`asset.frameTextures`以及`asset.forms.gear5`映射成FighterView所需的`CharacterPresentation`。

`CharacterPresentation.forms.gear5`包含`key`、`anims`、`attachments`、`textureDensity`、`frameTextures`和可选`foregroundFrames`。场景其它使用动画表、残影、判定对照或相机边界的位置，也必须根据真实`fighter.form`选同一对象；不能只改FighterView构造参数而把外部计算留在常态。

FighterView按实际`fighter.form==='gear5'`选择动画、帧纹理、根点、身体比例密度、连接点、投技前景和镜头边界。形态丢失时隐藏并记录`luffy/forms/gear5`，不借常态图。前景与身体保持同镜像、根点、缩放及世界坐标。退形后恢复常态，KO时是否保留形态由既有core状态决定。换角释放时连同形态的分页纹理一并释放，菜单图保持原来源。

`resourcePlan.gear5DownloadUrls(records, ids)`为可选的显式预热名单；原`fightDownloadUrls`行为保持，样板、旧版及普通预热不会仅因清单出现五档文件就自动下载。未选路飞时名单为空。实际形态加载由上述显式函数完成，失败仍需场景提供重试或返回。

## 运行合同与覆盖

五档runtime沿用schema2分页规则，角色仍为`luffy`，增加：

```json
{
  "formId": "gear5",
  "formEvidence": {
    "review": "full-coverage-accepted",
    "authorManifestSha256": "实际作者清单64位SHA256",
    "sourceHashes": { "显式来源key": "原PNG64位SHA256" },
    "frameSources": { "luffy/idle/0": "显式来源key" },
    "atlasHashes": { "atlas.png": "实际PNG64位SHA256", "atlas.json": "实际JSON64位SHA256" }
  }
}
```

上例为字段说明，不是可采用凭据。每个主体/前景attachment都要有真实来源映射，全部页的图像和坐标JSON要有哈希；HTTP加载逐字节比对页文件，再核解码尺寸、帧边界、画布与attachment尺寸、页归属、真实可见alpha及透明背景。正式来源原PNG不随运行包发布；原始来源与prompt/观察票据在作者清单阶段校验。

`validateGear5Runtime(value, luffyDef)`覆盖：

- `DEFAULT_ANIMS`中的25项战斗/胜负状态（不要求菜单portrait）。
- 常态仍可达的23个招式，去掉被替换的`sp_gatling/sp_bazooka/sp_rifle`及五档禁用的`sp_gear2`。
- `g5_elastic_rush/g5_bounce_slam/g5_rising_whip`三招和`g5_awakening`。
- `held_leg_flip/held_labubu_throw/held_twinkle_throw`三种条件受投；必须为单帧非循环、显式正ticks与实际裁切内grip。

每个招式exposures总tick必须匹配core数据；投技还需匹配真实连接后的throwExposures。`g5_awakening`两包都声明同一个36tick时间轴：0至23使用常态，实际提交后24至35使用五档包；两阶段像素按真实图制作，不能为多播几张改变逻辑时长。到期/疲劳/受投关系安全退出沿用core，不由渲染私自切形态。

这些结构和哈希检查只能证明资源身份、完整性与时序，不能证明五档身份正确、画面自然、接触准确或已经人验。

## 构建合同与命令

作者清单仍为schema1、`characters.luffy`。形态配置额外写`formId:'gear5'`，每个来源也明确`formId:'gear5'`；来源继续走既有官网来源、实际模型未知项、完整prompt、PNG和观察票据哈希验证。`formReview`缺省为`candidate-not-accepted`，样板不因此自动解锁；只有实际完整审查通过后记录`full-coverage-accepted`。

```powershell
.\run-d1013.ps1 -Program python -CommandArguments @('scripts/build_anime_atlas.py','luffy','--manifest','scripts/<显式五档作者清单>.json','--form','gear5','--check')
.\run-d1013.ps1 -Program python -CommandArguments @('scripts/build_anime_atlas.py','luffy','--manifest','scripts/<显式五档作者清单>.json','--form','gear5','--out-dir','D:/<本次候选目录>')
```

不传`--out-dir`时仅输出`public/assets/characters/luffy/forms/gear5/`；显式候选目录必须在D盘源码工作区之外，或恰为该标准形态目录。拒绝C盘、基础anime、其它角色目录及源码目录；`--out-dir`只接受单角色和`--form gear5`。默认构建拒绝带formId的配置，避免漏参数覆盖基础包。新形态输出目录先写README。替换已有候选仍需`--replace`及原有先备份/哈希核验流程，不自动删除旧页或旧包。

交付编码在原有六人、UI、FX显式参数之外追加`--gear5-manifest <作者清单>`及本轮独立`--report-dir`。只有选中基础路飞、已接受完整覆盖、常态与五档36tick觉醒都齐全且现有形态文件逐字节匹配重新验证的来源组装结果才编码。形态沿原有WebP/透明度/受保护前景无损规则；不重复打包UI、基础FX或音频，不覆盖普通anime逻辑URL；编码后自动刷新形态页的最终atlasHashes。交付参数报告记录该作者清单路径与SHA。

没有真实作者清单及完整素材前不运行生产编码；本轮只在内存合成测试中验证路径、映射与拒绝分支。
