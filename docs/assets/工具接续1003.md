## 人物图集替换与D盘备份

```powershell
python -X utf8 scripts/build_anime_atlas.py --manifest scripts/roster_aokiji_manifest0929.json --replace --backup-dir D:/one-piece-fighter-crossover-0922/roster-0929/baseline/atlas-backups1003 aokiji
```

上述`--backup-dir`是可复用的**备份根**；工具在其下创建新的`anime-backup-<id>-<时间>/`，不覆盖任何旧子目录。新的根和子目录先放README，保存`backup-inventory.json`再复制全部现有文件，核对原件/副本长度与SHA256后保存`backup-copy-after.json`。所有本次角色备份通过，才写新候选。UI和其他旧页一并保全；不删除任何文件。备份根不能位于`public/assets`内。`--check`不创建备份或写候选。

默认不传`--backup-dir`的旧命令继续可用。本轮批量制作应明确使用D盘。本说明中的目录只是接口示例，本次未执行该媒体替换命令。

## FX格式

旧schema 1及青雉/香克斯两帧配置保持兼容，PNG像素、布局和atlas JSON字节保持。新增帧或其余角色使用schema 2，不能给旧配置随意增加未声明帧。

以下是**格式示意，不能当作来源或运行资源**。实际填写已经审查的来源key和源像素坐标。

```json
{
  "schemaVersion": 2,
  "catalogs": ["scripts/roster_sources0929.json", "scripts/roster_marine_sources0929.json"],
  "maxCropEdgeAlpha": 4,
  "maxTextureSize": 4096,
  "characters": {
    "aokiji": {
      "frames": {
        "ice_lance_0": {"source": "reviewed_actual_source_key", "crop": [10, 10, 300, 180]},
        "ice_lance_1": {"source": "another_reviewed_actual_source_key", "crop": [330, 10, 300, 180]},
        "ice_impact": {"source": "reviewed_actual_source_key", "crop": [10, 230, 300, 300]}
      },
      "pages": {"p0": ["ice_lance_0", "ice_lance_1"], "p1": ["ice_impact"]},
      "animations": {
        "ice_lance": {"frames": ["ice_lance_0", "ice_lance_1"], "ticks": [2, 2], "loop": true}
      }
    }
  }
}
```

- `catalog`单文件或`catalogs`多文件必须二选一；同key跨表完全相同可复用，冲突则停止。
- `frames`每项只允许`source/crop`。没有目录扫描或推定帧；未知角色、未知来源、缺源图/提示词/证据、错SHA、空图、明显裁断alpha均停止。裁切边alpha最高为4，不对保留像素滤透明、重绘、变色或缩放。
- 同一原图同一裁切不能换名计成新帧；schema 2相同RGBA裁切也不能伪称独立姿势。需复用时动画引用已有帧名。
- `pages`省略时全部放p0；主动分页时必须按p0/p1顺序、每个帧恰好登记一次。单页超4096停止，要求明确分配页面，不能暗中缩小或丢帧。
- `animations`可省略；有动画时必须给真实帧名、等长正整数`ticks`和布尔`loop`。ticks按既有60Hz解释，工具不改core时序。多帧合同不等于正常速度动作已验收。
- schema 2输出`atlas.png/json`、必要的`atlas-p1.png/json`等和`fx-runtime.json`。FX合同包含实际page、framePages、anims、作者manifest SHA，供主集成接入播放；现有渲染不会因文件存在自动使用新动画。

FX构建的`--backup-dir`与人物工具不同：它是**本次唯一备份目录**，必须是D盘`roster-0929/baseline/`下未存在的子目录；`--report`也必须是独立新文件。旧页与合同在替换前全部按copy-before/copy-after保全。未使用的旧页保留，不删除。

## 运行编码接入

新增人物必须同时满足：

1. 由明确`--author-manifest`唯一拥有；官方源图/提示词/网页证据通过校验，已生成runtime、每页atlas和build-report的输出SHA一致，atlas的作者manifest SHA一致。
2. `--ui-manifest`明确包含该人物、没有关闭或blocked/rejected/unreviewed/disabled状态。UI原件SHA、角色命名空间、body/portrait范围、源密度裁切及保护RGBA均核验。已记录的相邻人物排除矩形可以复用，排除外不能改像素；无法复现的其他处理不会自动放行。
3. 每位给一份唯一`--fx-manifest`。工具只读重新准备实际来源裁切，逐字节核对全部运行FX页/JSON/合同；被改过的文件停止，不能只更新一个输出hash绕过来源验证。

工具登记了19位的运行FX路径，但未提供上述资料的新人物仍拒绝编码。FX配置不允许夹带未选角色。新人物UI和FX采用无损WebP，检查全部RGBA；身体普通页仍沿既有质量/alpha保护，带主体/前景的保护页继续无损，AVIF限制保持。音频继续依正式sampleManifest的`characterId`分银行，不自行采纳声音候选。

```powershell
python -X utf8 -c "import json,sys; sys.path.insert(0,'scripts'); import build_delivery_assets as d; plan,receipts=d.resolve_build_plan(['aokiji','shanks'],['scripts/roster_aokiji_manifest0929.json','scripts/roster_shanks_manifest0929.json'],'src/render/anime/rosterUiCandidates0929.json',['scripts/roster_aokiji_fx_manifest1003.json','scripts/shanks_fx_manifest1003.json']); print(json.dumps({'characters':[x['id'] for x in plan],'fxPages':[len(x['fxPages']) for x in plan]}))"
```

输出两位各一页，作者/UI/FX来源核对通过，现有FX与原两帧配置重建字节一致。没有把两位完整角色或声音验收写成通过，没有编码整套媒体。

待主集成完成首两位后，正常编码沿原入口，追加明确参数：

```text
--character aokiji --character shanks
--author-manifest scripts/roster_aokiji_manifest0929.json
--author-manifest scripts/roster_shanks_manifest0929.json
--ui-manifest <主集成已合并并审查的UI清单>
--fx-manifest scripts/roster_aokiji_fx_manifest1003.json
--fx-manifest scripts/shanks_fx_manifest1003.json
--report-dir D:/one-piece-fighter-crossover-0922/roster-0929/acceptance/<新的本次目录>
--manifest-output <本次独立候选deliveryManifest.json>
```

以上是参数片段，不是可直接执行的命令；完整包要同时给旧四位及其对应作者manifest，使用已发现的ffmpeg真实路径。新人物编码必须给独立报告目录，不能写回0915旧报告区。制作候选先使用独立manifest输出，主集成在实际完成、集中验证后处理正式登记与运行白名单发布。
