日期：2026-09-13。只处理已核实的 GPT Image 2.5 母版，不新增生图、不增加战斗动作，不解除完整动作门槛。此记录不表示完整游戏或浏览器画面验收完成。

## 发现与修复

标题、选人、结算此前已通过 `spriteFrame` 按 anime 配置取新人物，没有发现它们自动读取旧像素图。标题在没有 portrait 动作时取真实 idle：本机当前路飞站立纹理为 316×367、赤犬 350×424，标题在 1920×1080 画布上分别显示约 740、780 像素高，会放大战斗缩图。HUD 原来只有名字，没有角色头像。

本次从母版以 1:1 像素裁出完整人物，标题和选人改用这些静态界面图。头像只是在同一透明纹理内登记一个方形区域，不复制图像或占用额外纹理。HUD 根据实际 P1/P2 角色显示头像，右侧镜像朝内；每个头像为 52 布局像素，高清画布对应 104 像素。血槽仍为 336 布局像素宽，计时器大小和中心不变；局胜标记放在姓名行的内侧。结算继续显示获胜角色真实 `win` 动作，重赛、选人和标题的表现配置传递保持原实现。

这没有增加角色的战斗动作覆盖，不能用界面全身图替代缺失的攻击、KO 或胜利动作。

## 加载与异常

界面图是声明资源，随动漫人物加载。校验下载字节 SHA256、解码尺寸、裁切边界之后，以内容和坐标构成的不可变键注册纹理。重复进入和重赛会校验文件并复用同内容纹理。配置存在但图片缺失、损坏或尺寸错误时，人物加载结果失败，使用现有明确错误和重新载入入口，不把旧的已加载纹理标成此次成功，不自动回退旧像素人物。

战斗页和设置页按需诊断中的 `interfaceTexture` 显示实际界面纹理键。显示层遇到丢失的界面纹理时，标题和选人显示缺失提示，HUD 显示“头像缺失”，不借用其他角色或旧图。加载并行 UI 解码收尾后才报告结果，避免立即重试时上一轮临时图片 URL 仍在释放。
