## 前投/后投并不是两套姿势

路飞`throw_fwd/throw_back`当前共用5个来源帧：reach、hold、release、rise_guard、basic_idle；throwExposures也相同，总44tick。它们不是10张独立姿势。

| 已连接后tick | 真正显示的来源帧 |
|---|---|
| 0—5 | throw_reach |
| 6—21 | throw_hold |
| 22—29 | throw_release |
| 30—35 | throw_reach（回收，复用已存在姿势） |
| 36—40 | rise_guard |
| 41—43 | basic_idle |

前后投holdOffset均34，真实释放22；后投仅在释放时按core换边/翻面。受投者朝向始终与攻击者相反；不可在制作时猜一张额外“后投持有”来改变连接时间、根距或原44tick。

普通`thrown`当前是单张`thrown_resist`，自身exposure=1不是实际只抓1tick；实际持有由攻击者throw时钟控制。普通受投没有专门grip socket，本基线保留chest/palm等实测点，仅作普通接触参考，不新增抓胸规则。

当前textureDensity=2。准确换算为：
`世界坐标偏移 = (runtime socket - runtime root)/(2×textureDensity)`，即除4；水平再按facing镜像。不要只除density，否则误差正好翻倍。

攻击者面朝右时，受投者逻辑根在`[holdOffset,0]`，其图水平镜像。于是：

- LABUBU抱腿：30−13.967213=16.032787，y=−13.180328；与既有LABUBU`sp_leg_flip/1`的grip_gap一致。
- LABUBU普通投：31−19.4=11.6，y=−26.6；与`throw_fwd/1`grip_gap一致。
- 星星人普通投：32−22.75=9.25，y=−34.25；与`throw_fwd/1`grip_gap一致。

这些是现有元数据的静态复算，浮点尾差约机器精度；不是本轮新增浏览器或新五档接触验收。青雉/香克斯的既有手握点与共享反应也在baseline逐项列差，不能把通用静态图推定为所有体型/墙角通过。

## runtime导出参考与新图制作边界

`runtime-guides/`10份是当前atlas原尺寸矩形直接提取，标记“runtime-derived guide”，不称原始模型下载。路飞这些帧无foreground分层；如果后续参考含分层，只有body+foreground以原选择像素重构后才能使用，不能漏手臂/重复alpha叠加。提取已验证矩形未旋转未trim、PNG回读像素一致，记录atlas页/坐标JSON SHA和切块坐标。

根代理可以用上面的**原crop**作为姿势参考，并同时给已确认白形态母版约束身份。新五档必须由官方网页实际生成相应身体/姿势，保持真实抓握接触目标；不能程序改色、旋转旧图、拉伸肢体、随意改变逻辑根距来冒充。新图需要按自己的统一标尺、真实脚点/脚踝/前脚掌重新测量登记，不能把旧root数值直接贴进尺寸不同的新图凑过。前景需要真实手臂原像素分层时，沿现有显式mask/多边形规则处理，不用参考图自动生成新人物。

本轮只做源图/裁切/runtime元数据和静态握点核对，未跑6×6浏览器、未改既有角色或生产清单。原速、双朝向、抓住/释放/墙角、形态到期安全收束仍由新五档制作后实际验证。
