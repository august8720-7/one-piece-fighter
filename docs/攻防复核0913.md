## 修复证据与取舍

1. 原pendingBlock在首次看到起手时计算完整持防时长，等待reaction后仍原样执行。普通难度、种子6、路飞轻拳挥空的隔离场景：第13帧才按后防，此时轻拳已收招，随后一直按到第27帧；修复后不执行这次过期防御。赤犬重拳威胁的同类场景，在第13帧启动时只按当前剩余攻击阶段计算，未把已等待12帧再计一次。
2. isThreat原来把恢复阶段也当威胁；受击硬直结束后还可能再次选择防御已经在收招的拳。现在只有startup/active构成近身打击威胁，仍需真实距离判断；飞行道具依旧由独立入口处理。
3. 原确反分支额外限制distance<closeRange+50，即路飞120、赤犬125逻辑像素，而其重拳本来能覆盖更远距离。现在由既有actionCanReach按实际候选动作范围过滤，不先用近身区间截断，同时要求已观察满当前难度反应帧。选择意愿仍使用原comboWill，未加血或提高blockChance。
4. 继续保留粗略可达性边界：它使用当前姿态、显式伸出肢体和空中速度/重力包络筛掉明显空挥，不预测玩家下一帧输入。它也未证明所选招式总能在对手收招结束前接触，不能把该选择入口等同必定成功的确反。
源码只改`src/ai/cpu.ts`；新增回归在`tests/ai/cpuTiming.test.ts`。`src/ai/types.ts`的SHA与改造基线完全一致，角色策略表也在下述源文件一致性范围内。完整前后探针见`cpu-block-probe-before0913.json`与`cpu-block-probe-after0913.json`。
