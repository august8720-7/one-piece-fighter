# 声音体验修复计划0914

状态：用户已于2026-09-14批准并要求执行，当前实施中，未验收项不计完成。延续精美动漫街机与日语人物原声方向，保留当前人物、招式、伤害、判定和比赛规则。本轮目标是让移动、等待和整场比赛都有合适的声音，并保住打击与操作反馈的清晰度。

## 已核实的问题

2026-09-14核对当前源码、运行声音清单和已公开版本的交付记录：

| 问题 | 当前实现 | 对体验的影响 |
|---|---|---|
| 移动、等待没有人物声音 | `FightAudioEvent` 没有移动或待机事件；两角语音清单各只有 attack/hurt/ko/win | 平时人物缺少声音，主要靠施放技能或受击才能听到角色 |
| 没有背景音乐 | 57个采样配置分为48个音效、8个人物语音、1个环境声；没有 music 分组或曲目。唯一环境声为 marineford_ambient | 环境声不能提供旋律、节奏和比赛气氛 |
| 普通攻击缺少出力声 | `audioCues.ts` 的 start 分支仅为 sp_/ult_ 招式触发人物出力 | 普通拳脚到特殊技的声音表现不连续 |
| 声音状态说明不完整 | 快捷状态默认检查音效分组；设置页还保留“人物台词尚未完成听辨”的旧文字 | 既有声音已加载，容易被理解为所有声音场景已经齐全 |

依据：`src/audio/audioTypes.ts`、`audioCues.ts`、`AudioEngine.ts`、`sampleManifest.json`，`scripts/voice_manifest.json`，`src/render/scenes/SettingsScene.ts`，`docs/全动作与声音交付清单0913.md`。上述为当前文件事实；本次没有重新测量用户扬声器输出。

上轮公网音频下载、解码和播放验证有效，但没有覆盖音乐与移动/待机声音，不能据此宣布声音体验完整。这一缺口应当补进验收。

## 修复后的体验

以下秒数、片段数量和音量变化是首轮调校目标，不是当前已经实现或测得的结果。

| 场景 | 修复内容 | 触发与限制 |
|---|---|---|
| 走路、后退 | 路飞轻脚步，赤犬较沉的鞋底声；补充适合移动的日语短声 | 脚步跟随可见落脚节拍。每回合首次持续移动约0.4秒后可触发一次短声，后续移动语音至少间隔12秒；短按、反复转向不刷语音 |
| 冲刺、起跳 | 短促出力、衣物或披风运动声，衔接现有落地声 | 用真实状态开始触发；移动、冲刺和起跳共用低优先级语音冷却，不为每一步重复喊叫 |
| 站立等待 | 角色各自的简短日语台词、轻笑或呼吸短声 | 连续站立约6秒且最近2秒无攻防接触后，安排一句；之后至少间隔18秒。训练场也有声，暂停和加载时间不计入等待 |
| 普通拳脚 | 补齐轻短出力声，让普通攻击和技能都有角色反馈 | 按出招实例触发，使用短片段和冷却；连打不每拳播完整台词。现有技能喊声、受击、KO和胜利声音继续保留 |
| 标题、菜单、选人 | 一首无歌词主题音乐 | 用户点击或按键解锁后开始，三个页面间连续播放，选人不把音乐反复从头启动 |
| 正常战斗、训练 | 一首有旋律、节奏明确的战斗音乐；训练默认适当降低力度 | 开战时切入，同一整场比赛换回合不重启；环境声在较低音量下保留 |
| 整场胜负、结算 | 胜负短音乐收尾，突出人物胜利声音 | 清理战斗短音，音乐平滑切换；重赛只启动一份战斗音乐 |

待机台词还需通过语义检查，不能把“受伤惨叫”当呼吸，或把明确招名当走路台词。移动时应当能听出人物在行动；待机时应有角色存在感，但不能让双方不停抢话。

两人的低优先级闲聊交错安排，已有闲聊播放时另一人不抢入。攻击、受击、KO立即取消本人的待机/移动长声；未能播放的闲聊直接丢弃，不在招式结束或解除暂停后补播。正常战斗反馈可以并发，不为了闲聊调度延迟打击声。

## 素材方案

- 人物原声优先从已有两角来源和候选库筛选，复用已经确认的角色声线。本轮新增目标为每角至少2段不同的待机短声、2段移动/出力短声；普通攻击优先复用语义合适的短出力，不机械凑数量。
- 每段记录来源区间、SHA256、用途、听辨结论；有准确台词时再记录原文和译文。用户之前的声线确认继续有效，但不能扩展成任意新片段的台词语义也已确认。候选不足就定向补找，未核验的素材继续列缺口。
- 背景音乐推荐无歌词的热血管弦、战鼓与适量电吉他：菜单稍克制，战斗有持续节奏。先选1首菜单循环、1首战斗循环及胜负短收尾，避免单一低频轰鸣充当配乐。
- 曲目优先采用来源与公开网页使用条件明确的现成素材，并记录作者、来源和所需署名。当前没有已经核实并采用的背景音乐，不承诺尚未取得的具体海贼王原声曲目。
- 所有正式片段先试听、去掉首尾无效静音、校准响度和循环接缝，再接入游戏。音乐使用压缩音频与流式播放，避免把几首长曲全部解码进内存。

本轮不需要新增图像，也不需要使用 Pro 做生图或重新规划美术。

## 实现范围与关键处理

1. **加独立音乐通路。** 扩展 music 音量与状态，音乐通过与现有音效相同的总音量通路输出。保持单个 AudioContext，采用可跟踪的媒体播放实例；只维持当前曲目，交叉淡入淡出时临时最多两份。音乐的暂停/恢复保留播放位置。
2. **拆开比赛清理和音乐切换。** 当前 FightScene 在回合变化、重置和退出时多处调用 stopAll；直接把音乐塞进去会反复断曲。增加明确的战斗短音清理与场景音乐控制，按标题、战斗、结算状态切曲。同曲目重复请求无操作，跳转期间过时的异步加载不得把旧音乐重新启动。
3. **加人物日常声音调度。** 从现有战斗状态和实际动画节拍读取移动、落脚和等待，不读取未来输入、不改核心规则。按玩家实例分别管理计时与变体，镜像对局也不会共享冷却。计时只累计有效游戏时间，掉焦、暂停、回合结束与训练重置清理旧请求。
4. **补普通技语音映射。** 保留现有材质音效和真实接触事件，单独为普通攻击添加短出力选择；不破坏三段伸缩音效，也不让已有特殊技重复喊招。
5. **调整混音和设置。** 设置显示音乐、人物声音、打击/技能、环境四组。人物语音出现时音乐短暂降低约6dB，结束后平滑恢复；这是初始试听值，不固定当作最终听感。提供对应分组试听，音乐试听也可停止、切页即清理。
6. **保留旧设置与准确状态。** 旧存档仅为新增 music 补默认值，保留静音、总音量和原三组音量。按分组区分未解锁、零音量、下载/播放失败与正常；音乐失败可以重试且不阻断比赛，交付验收仍不能把它算完成。修正已过时的人物声音说明。
7. **补发布清单。** 声音来源与映射继续由显式清单管理；音乐另有曲目与循环信息清单。更新 `scripts/apply_voice_manifest.py` 支持新语音用途，更新 `scripts/packagePages.mjs` 收集新增音乐和声音，防止只在本地听得到。新增素材目录之前先补项目结构约定。

预计涉及 `src/audio/`、声音设置/试听组件、标题/选人/比赛/结算场景、语音映射与静态打包脚本。新增文件按职责放入这些已有模块，不重新搭建整套引擎，不扩大到新角色、新舞台或其他玩法。

## 实施顺序

1. 保存当前线上构建与声音清单，完成候选筛选和来源记录；同时接通音乐分组、播放生命周期和旧设置兼容。
2. 在训练场完成“站立等待→前进后退→冲刺/跳跃→普通攻击→特殊技”的正常速度有声样段，内部试听并修正重复、抢话和遮盖。
3. 接入整套菜单、比赛和结算音乐，验证暂停、切页、回合与重赛；再校准人物、音乐、环境和打击的整体音量。
4. 工程检查和真实有声试玩通过后打包，更新原 GitHub Pages 地址，核验公网首次加载。中间片段由代理自行检查，不逐条要求用户确认；本轮交付后集中反馈听感。

## 放行标准

| 验收 | 必须观察到的结果 |
|---|---|
| 人物等待 | 每角独立在训练场站立60秒，出现合适的待机声音，首句约6秒后出现；整个窗口约2～4次，不连续重复同一段，也不在受击中突然说闲话 |
| 移动 | 首次持续移动能听到短声；慢走、后退、冲刺的脚步跟动作。连续点按/转向不刷台词，停止移动后没有残留脚步 |
| 攻击接续 | 普通拳脚、技能、受击声音都能听清； idle→出招、走路→受击会取消不合时宜的闲聊，命中音不延迟 |
| 音乐 | 首次点击后标题有真正配乐；选人、开战、换回合、结算和重赛切换正确，循环接缝无明显空白或爆音 |
| 停止与恢复 | 暂停/掉焦后不继续闲聊，战斗声音停止；继续时音乐从暂停位置恢复，没有历史语音补播。静音、零音量、设置试听和退出各自正确 |
| 失败恢复 | 新设备设置、旧存档、断网、音乐/语音404、加载中切页、失败重试分别验证；错误说明对应实际分组，没有“音效就绪即全部就绪”的误导 |
| 稳定性 | 四项工程检查通过；增加计时、抢占、音乐切换与旧设置兼容测试。实际浏览器持续交战15分钟并反复重赛，检查声音实例、内存和帧时间；不使用后台被节流的窗口得出前台性能结论 |
| 公网 | 原访问链接可玩，新增音频逐项 HTTP 与内容哈希一致；首次解锁、人物等待和走路、完整人机胜负及重赛均在公网复核 |

交付修复后的同一访问链接、一段正常速度且含浏览器实际音轨的前后对照、素材来源/覆盖清单及验收记录。代理必须试听成品混音；“文件存在”“播放计数增加”和单元测试都不能代替听感。用户设备实际听见和最终满意度仍由集中试玩反馈，未解决项如实保留。
