# 海贼王格斗整体品质升级计划 0912

状态：2026-09-12，已完成网页 Pro 独立咨询与本地审查；用户明确要求“现在开始全力执行计划”后，已制作并接入路飞伸臂与赤犬大喷火双机制小样，实机功能及工程检查已有证据，尚待集中美术/手感审阅。当前视觉限制与未完成项见`整体品质实施记录0912.md`。旧可玩构建和全部成果保留，下面的阶段与验收门槛继续有效，不把功能检查通过标记为整轮完成。

推荐方向：**保留格斗底座，用 GPT Image 2.5 统一人物和动作；先验证路飞伸臂与赤犬熔岩能力的两个小样，再批量制作，最后用完整对局验收品质。** 网页原始建议与证据边界见 [网页 Pro 规划建议](网页Pro规划建议0912.md)，取舍见第 9 节。

## 1. 这次真正要改什么

目标是一个**画风统一、身体动作可信、攻防清楚、操作跟手、愿意反复玩的动漫 2D 横版格斗游戏**。沿用两年后路飞、赤犬、顶上战争海军本部、两角色一舞台、1v1、本地双人/人机/训练；“横版动作”在当前共识下不扩展为卷轴闯关。

【事实】当前实机画面把掌机像素人物、精细平滑的熔岩贴图、细节丰富的舞台和亮黄色界面放在了一起。旧人物图中的拳火还与新熔岩拳重叠。问题同时涉及画风、身体与技能连接、画面主次。

【判断】需要重做整体表现，但没有证据要求推倒格斗引擎。输入、固定步长、碰撞、回合、训练、比赛和重赛已经提供可用底座。把这些全部重写会增加回归风险，也不会自动解决美术问题。

**最强反方是：人物都换成 GPT 生成，可能得到一批漂亮但不能连续播放的姿势。** 同一个模型不会自动固定脸、服装、比例、脚点和动作轨迹。本计划的关键变量是能否稳定制作一段“正常速度、真实输入、符合命中时序”的角色动画，而不是单张图能否更精美。

【未知】Image 2.5 在本项目参考图与制作流程下能达到怎样的连续性、返工成本和生产速度。以样板测量，不承诺一次生成完整精灵表，也不凭旧估算承诺工期。

## 2. 路线与边界

| 路线 | 判断 |
|---|---|
| 保留像素人物，把背景和特效统一回像素 | 制作风险较低，但不符合用户此次明确的精美方向；只保留旧版作为可玩基线，不默认退回 |
| Image 2.5 固定角色设计、关键姿势、受控补帧，输出逐帧图集 | 推荐。可复用现有运行时，先验证身份与动作一致性，再扩展产量 |
| 全面运行时骨骼或 2.5D 人物 | 不作为本轮主路线。部件工具可辅助小幅运动；大透视、遮挡、橡胶变形仍需专门原画。若样板证明需要，另作针对性试验 |
| 重写引擎 | 不采用。与当前主要问题缺乏直接因果关系 |

保留：确定性 60 Hz 模拟、输入缓冲与朝向修复、碰撞/防御/投技/取消、比赛流程、CPU 输入接口、训练工具、投射物结束事件、音频缓存与播放管理、旧构建与回退。

重新设计：人物造型与连续动作、身体和技能之间的连接、特效节奏、舞台与人物的对比、血条/气槽/菜单视觉、实际采样和原声混音。新生成的背景和特效是候选素材，也接受修改，不成为不可动的基准。

美术替换阶段锁定伤害、判定范围、起手/持续/收招时长与镜头覆盖范围。后续若发现真实玩法问题，先修输入/状态/CPU的可复现错误；涉及战斗数值的变化单列依据和对照，不为迁就原画偷偷改规则。

## 3. 先建立一个同屏标准

推荐“清晰轮廓、有限阴影层次、动漫街机动作”的方向。人物保持角色辨识度和连贯身体结构，不采用写实人物配卡通火焰，也不把每个部位都画成高亮材质。

- **人物**：锁定路飞两年后造型与赤犬服饰；设定页统一头身比例、轮廓、衣物结构、颜色、光源和战斗视角。站姿身高、原画尺度、脚底锚点按角色固定；蹲、跳、伸臂不能因裁切外框变化而重新拉满画布。
- **技能**：与人物共享线条、阴影和色彩。橡胶看得出拉伸与回弹，熔岩看得出块体、热核和碎裂；发光不是形体本身。
- **舞台**：海军本部建筑、海湾、军舰、冰壁与战损石板保留身份。交战带降低细节和亮度，脚下有接地关系；先验证整幅构图，再决定哪些层真正需要独立视差。同一原图裁出的背景和石板带先保持匹配运动，不能把它们冒充独立透视层强行错速移动。
- **界面**：血量、气槽、局数、计时器优先易读，头像和装饰沿用同一人物设计。深色底、克制的角色强调色取代整条高亮抢眼；受伤延迟条、可用气量、选中/禁用状态有区别。动态文字、数值和按钮用代码呈现，不能生成为不可更新的截图。
- **实际尺寸**：保持现有世界坐标和战斗尺度，在当前布局及至少 1280×720 的实际显示下审查线条、透明边缘和阅读性；高清通过原画、滤波与渲染验证实现，不靠放大像素素材。不要把显示分辨率变成新的碰撞坐标。

输出一张同屏构图及规则页：路飞、赤犬、舞台、代表技能、HUD 同时出现。静图用于定风格，不计为动作完成；不单独逐张征求确认，集中在可操控样板验收。

## 4. 人物与动作怎么生产

顺序为：**固定设计参考 → 动作时序卡 → 关键姿势 → 必要中间姿势 → 清理与图集 → 实机校验**。

每个动作先从真实招式表取出起手、首个/最后有效帧、发射时刻、投技放人时刻、可取消窗口和恢复行动时刻；定义预备、发力、接触、回收的姿势，并记录需要的肩/手/脚连接点。视觉帧按逻辑时段安排停留，不机械均分，也不要求每秒 60 张不同原画。

Image 2.5 负责人物原画、透视变化、拳脚转面、受击重心、局部膨胀和橡胶形变。生成时反复引用同一组已定参考，一次集中解决一个动作或相邻姿势，检查衣服、脸、肢体数量和身体连接。九宫格只可作为检查布局，不能默认裁开即得到连续动画。

受控几何变换只用于已有画面内的轻微呼吸、衣摆或有限部件摆动；它不能凭空补出被遮住的胳膊，也不能把整个人拉长当伸臂。复杂中间帧仍由指定模型生成并逐张检查。最终离线输出透明逐帧图集，不增加独立于模拟的动画计时器。

朝右作为基础制作方向，朝左统一镜像并实际检查；疤痕、服饰文字和非对称配件若镜像破坏辨识，使用有记录的朝向修正或专用帧，不能仅检查一个方向。图像可裁切，但裁切前后原始画布尺寸、偏移、根点与连接点必须可追溯；跳跃保留根点到身体的偏移，不能把图片底边误当脚下。透明边缘需在亮/暗背景检查。

现有管线的必要调整：

1. `build_sprite_atlas.py` 的整数倍最近邻放大、`pixelArt`、固定宽度且高度不断增加的图集打包，改为显式风格与尺寸配置，并在样板时检查纹理上限和内存。新旧图集分开配置滤波，不能指望同一纹理逐帧切换采样方式。
2. `spriteAnimations()` 改为明确视觉时段和帧停留，不把所有新素材标成像素；保留旧格式兼容。
3. `FighterView` 不再依赖旧 `artSource` 名称判断是否播放连续帧，否则新图可能退回少数逻辑姿势。新版用明确能力标记，缺图按角色完整回退，不在一个动作中随机混用新旧风格。
4. `FightScene` 移除“非像素人物在气球/巨拳时整人放大”的表现假设；局部变形有专门姿势，人物基准尺寸稳定。
5. 原画、帧时序、连接点、镜像规则和素材来源用同一显式清单管理。优先保留当前 atlas 接口；若全量纹理超过浏览器上限，再采用有证据的分页，不先开发通用动画编辑器。

## 5. 身体与技能作为一次攻击制作

表现分为身体动作、能力主体和装饰层，三者有明确分工。身体图已包含的拳头/火焰不重复叠；连接点随视觉帧变化，不能把纹理直接拉伸到矩形攻击框就算完成。路飞伸臂遵循招式的固定轨迹与射程，不能追着对手自动伸长。附着能力随招式打断/取消清理，已经发射的对象继续服从核心生命周期。

| 技能 | 制作要求 |
|---|---|
| 路飞伸臂、重拳 | 肩—上臂—伸长段—拳头连贯；第一有效帧能看见真实攻击前缘，回收与收招一致。残影辅助速度，不替代手臂 |
| 机关枪、暴风雨 | 身体发力与拳影分批出现；接触闪光和命中音由真实命中段触发。装饰拳影不能暗示额外命中次数 |
| 巨人拳、火拳铳 | 局部巨拳与正常躯干连续；火焰包裹拳而不重复画拳。空挥不出现受击爆燃 |
| 二档、气球 | 二档蒸汽依附身体，气球有局部形变；状态开始、维持、结束和弹反响应清楚 |
| 赤犬大喷火 | 当前是近身持续判定：身体发力与巨型熔岩拳保持连续，攻击前缘对应当前判定；不能画成脱手后继续飞行的独立伤害物 |
| 犬噛红莲 | 身体蓄力→犬头形成→脱离→飞行→实际接触；犬头保留口鼻与下颌轮廓，脱离时刻服从真实投射物生成事件 |
| 流星火山 | 普通三发、强化八发按既有逻辑时机下坠，拳块、拖尾、接触、余烟依次发生。不是同时铺满全屏火焰 |
| 地裂、冥狗、熔岩化 | 地裂跟随实际攻击带，冥狗强调集中贯穿或抓取，熔岩化表现身体局部熔解与复原；不能共用一个球 |

命中、格挡、相消、落地、超时、出界和回合清理继续读取真实事件，清理不爆炸。装饰烟火可越过攻击框，但不能形成看似可伤人的新主体。关闭技能名仍能分清招式；关闭装饰特效仍能看清身体发力与接触。

黑底素材分开处理实体、发光和烟：实体保留深色岩壳与线条，发光单独混合，烟保留透明层次。当前处理脚本按像素亮度估算透明度，有误伤深色实体的风险；新版本不能继续对所有素材套同一阈值。赤犬原图上中格火尾触及画布边界，已本地目检确认；不能靠裁切补回不存在的尾部，需要时返回 Image 2.5 重绘。先修候选质量，再判断能否复用。

### 样板的通过、返工和停止条件

样板使用独立训练入口，预先列出可达状态。搓招必经的蹲姿、防御及受击也需要最小姿势；通过训练输入/招式白名单限定试制范围，界面明确它是限定动作样板，不改变核心时长、判定或正式模式。未制作的跳跃、投技等不在这个入口开放，转入基础攻防阶段验证，不能触发后靠缺图回退掩盖。素材加载失败时才按完整角色回退并标明失败。

**通过**：实际大小正常播放，脸/衣物/比例稳定，脚点无无故跳变；轻拳干脆，伸臂连续；空挥、命中、格挡、收招的区别可读。用键盘完成出招、木桩反击导致的受击打断、清单内合法取消，暂停/恢复与命中定格后不补播旧动作。逐帧核对第一/最后有效帧、恢复行动帧；发射帧仅对含真实投射物的动作检查。用户认可同屏品质与操作感觉后放行。

**返工**：身份漂移、滑步、断肢、拳未到就命中、看似收招结束却不能行动、贴图遮住敌人、旧拳与新拳并存。返工原画、连接点、透明边缘、视觉时段或素材风格，不延长硬直、不扩大伤害区。

**停止扩产**：指定模型无法核实；针对参考/姿势/接入原因修正后仍不能得到可信的连续样板；只能靠粒子遮盖或全身缩放成立。保留失败证据，缩小变量重新试制作方法；不无限生成同类图，不悄悄换模型或回退画风。此时先处理方法问题，不继续堆全角色产量。

试制默认一轮初稿、一轮针对原因的返工；同类关键问题仍未解决时，先交付失败对照与方法调整，不自动开始第三轮同样的批量提示。这是控制返工的计划边界，不是对模型成功率的预测。记录每动作候选/采用数量、返工原因和实际处理用时，再估算剩余制作量。

## 7. 声音、界面与耐玩性同样纳入样板和整场验收

声音沿用采样优先的播放管理，但真实内容仍须完成：源文件→切片→台词/角色核对→响度处理→事件映射→实机试听。路飞橡胶张力与回弹，赤犬低沉燃烧、爆裂和碎岩；轻击、重击、格挡、挥空有区别。没有对应招名可用同角色通用出力并记录，不能用另一角色或 TTS 冒充。

喊声按出招实例播一次，多段冲击按实际段播放，连续机关枪避免堆积长音尾；SFX、人物、环境独立音量。首屏真实点击/按键后验证声音解锁，不能只在已解锁的调试页面试听。暂停、静音、出招表、重赛、切场景和退出都验证停止与恢复，不积压旧声音。环境声低于攻防和语音，不用响度代替力度。

HUD 的血条变化、连段计数与消耗气量来自真实状态。训练帮助默认折叠次要信息；键位与左右朝向提示准确；新手教学必须实际挡住攻击，不以按后退冒充成功。菜单、暂停、结算和重赛用统一布局，保持键盘可用；手柄需要真实设备验证，没有设备就不标完成。

CPU 重点复现“反复靠近重拳”策略，先区分决策漏洞和招式本身缺少反制窗口；前者检查距离判断、防御与惩罚选择、反应延迟，后者单列平衡评审，不简单加血或读当前按键。用同一输入策略、多组种子和换边记录验证修复；自动胜率只能提示问题，不能证明人类觉得好玩。最终安排非开发者分开多次体验，记录：操作能否表达意图、为何受击是否清楚、角色是否有区别、退出原因、是否主动再来一局；尚未参与就明确“真人复玩未验证”。

## 8. 验证、来源与交付

美术替换前后，冻结同一核心/角色数据版本、随机种子和初始状态，重放同一逐逻辑帧 `InputFrame` 记录，逐帧比较 `WorldState`、命中事件和投射物结束事件。画面和音频实例不在核心相等断言内，也不直接拿核心版本不同的历史旧构建比较。另做正常速度实际操作，验证“看起来能行动”与“真实能行动”是否一致；两次真人按键不是可假定相等的重放输入。投射物相消、弹反、落地、超时、重置和回合结束单独覆盖。

性能从样板就记录图集尺寸、加载时间、活动纹理/特效/音频实例，正式版本再完成连续十五分钟对局和密集效果检查。记录测试电脑、浏览器、显示分辨率、帧时间分布和资源随时间变化，目标是流畅的 60 帧体验；不能只给平均 FPS，也不能凭旧像素版结论判断新原画显存。采样、解码和纹理预加载不在首次命中时阻塞。PNG 压缩大小不是解码纹理内存，RGBA8 基础纹理的估算为宽×高×4 字节，另有平台开销；按实际纹理上限与测量决定分页，并先更新“一角一张图”的项目约定。

所有 AI 图像，包括人物补帧和重绘，必须通过官方 ChatGPT 网页、核对 **GPT Image 2.5** 标识后生成。提示词、参考图哈希、生成时间、会话、页面型号截图/依据、原始文件 SHA256、处理脚本及采用/失败状态留档；衍生文件关联父文件哈希与处理步骤。规划使用的 `6 Pro` 与绘图的 `Image 2.5` 分开记；不把提示词中的型号当验证。哈希证明文件未变，不能单独证明模型来源。

原始图继续放 `public/assets/generated/source/`，人物候选处理图在 `public/assets/characters/<id>/` 下隔离保存；正式 atlas 在样板批准后按清单切换。原声、录音和来源包沿用本地音频目录，来源文本放 `docs/assets/`。新目录创建前先补项目约定；不删除旧素材，不提交版权图音，不覆盖唯一旧构建。回退按完整人物或完整旧构建进行，不把混合风格称为正式完成。

最终交付：

1. 可打开、可操作且绑定代码/素材版本的本地游戏，仍通过 `开始游戏.cmd` 启动；不自动公开部署。
2. 正常速度、有声音的旧新对比与完整比赛记录，标明真人操作或脚本驱动；不能只交剪辑宣传片。
3. 人物/动作/技能覆盖清单、复用与未完成项、原图/原声与生成来源记录。
4. `typecheck`、`lint`、`test`、`build`、浏览器流程、画面、试听、性能、真人/手柄的分项验收结果。

规划时的基线：旧可玩版已有历史工程和浏览器验证；新背景与特效已有三份原图和开发版表现，当时尚未制作新人物、真实音频清单为空。用户随后已批准实施；当前原图、音频采样、样板接入和验证的实际进度以 `整体品质实施记录0912.md` 为准。计划中的放行条件继续有效，不把开工或素材候选写为最终通过。
