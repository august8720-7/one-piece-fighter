# 项目优化计划 0911

目标沿用已确认的“可反复玩的朋友试玩版”：路飞 / 赤犬、一个舞台、本地双人、人机和训练。用户本次要求先规划再实施；本轮在既有架构内修补，不更换人物或重写格斗核心。

## 当前判断

【事实】最新工作区已增加六步引导、WAV 音效与技能表现。开工基线为 13 个文件、122 项测试通过。主分支最近提交仍为 `19ed4e4`，工作区有大量既有未提交变更，必须保留。

【事实】四张 JPEG 仍缺连续走路动作。正式加载器会在任一文件失败或 2.5 秒后提前结束，且不会在正式图片解码失败后再加载 placeholder。引导把后退当作防御成功；特殊技文字缺少斜方向的具体按法。训练逐帧没有明确恢复操作。自动对局脚本后续回合的开始时间没有可靠重置。

【判断】本轮先提升教学、资源可靠性和重复对局流程。继续堆演出无法解决这些问题。完整走路动画仍需有来源的精灵表和单角色样板验收。

## 执行顺序与验收

| 顺序 | 本轮工作 | 验收 |
|---|---|---|
| 1 | 引导以实际命中 / 格挡为准；特殊技明确“下、下+前、前+拳”，随朝向和改键更新；连段必须是本步骤轻拳接重拳；跳过与完成分开 | 两角色可按正常输入完成六步；空挥、后退、旧连击不能误通过；跳过不会写成已掌握 |
| 2 | 素材按角色独立加载、等待真正完成；正式资源失败再试占位；限制请求等待；复用有效纹理 | 正常、慢响应、损坏 PNG、缺失素材四种情况可进入游戏；一个角色失败不拖坏另一角色 |
| 3 | 清理场景重新进入时的旧引导和调试状态；逐帧可恢复；冻结期间不吃掉下一步输入；离开窗口自动暂停；返回选人保留难度 | 重开 / 设置返回 / 出招表 / 慢放与逐帧 / 切出窗口实际浏览器验证 |
| 4 | 修自动对局回合计时，参数校验与同种子换边记录；核对 AI 防御反应路径，仅修可复现错误 | 回合独立计时测试；固定种子可复现；落盘结果区分自动对局与真人平衡，不凭胜率直接改伤害 |

## 决策记录

- 继续以 `升级路线0910-修订.md` 和 `AGENTS.md` 的人物基线为准；本轮不生成、替换角色美术。
- 提高教学标准：之前“退后也算防御”容易过关，却不能证明玩家会挡攻击；改为真实格挡，同时让木桩主动靠近出拳。
- 让资源失败有完整回退；慢网络不应把正常人物误判为缺失。
- 自动对局仅提供问题线索。胜率受 AI 策略与角色使用方式影响，不能直接代表朋友间强弱。
- 修改前相关文件备份至系统临时目录，保留原图与其他未提交工作。禁止删除、推送或公开部署。

## 完成要求

`typecheck`、`lint`、`test`、`build` 全部通过；浏览器检查真实人物和完整流程；记录修复前后的证据。更新本文件结果和总计划状态。真人复玩、真实手柄、正式连续动作仍单独验收，不因代码检查通过而标为完成。

## 实施结果

本计划的教学、资源、输入和流程修补已接入；后续用户批准扩展到战斗手感和连续精灵，最新范围及验收见 `游戏复审与改进方案0911.md`。本文件中“本轮不更换人物”是此前的范围记录，已被新的明确授权取代。

浏览器已实际完成六步教学并进入有限血气的困难人机，验证逐帧方向锁存、暂停/设置返回、回标题再进入、出招表以及整场比赛/重赛。图片延迟、损坏、正式文件缺失、正式与占位同时缺失的四种资源回退均可继续对战。结果与证据路径汇总在新方案，不把这些自动检查写成真人畅玩或手柄验收。
